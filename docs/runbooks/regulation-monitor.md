# 异动监控发布与验收

## 边界

`regulation-monitor.v1` 是独立系统测算，不是正式公告认定，不复用开盘啦次数。
GET `/api/v1/regulation/monitor/candidates` 固定收盘观察名单；POST
`/api/v1/regulation/monitor/query` 最多查询 50 股当前条件。两者只读、共用 API key。
同一页必须携带同一个 calculation_id。409 后重载名单，禁止偷偷切换批次。
404 基础未发布和旧服务端点不存在必须分别提示，禁止空数组冒充成功。

## 数据条件

自 2026-10-01 代码更新起，三个监管基准的缺口采集使用 Tushare `index_daily`
（ADR-0048 澄清、Issue #69）；须配置已有 Tushare 凭据，不输出或提交凭据。
独立 Raw schema 为 `tushare.index_daily.v1`。只补经批准的缺口，不覆盖历史 BaoStock 事实。
数据库现有来源约束已允许 Tushare，无需新迁移。常驻 Worker 须经另行批准部署/重启后
才采用新代码；受控补数不等于已经切换调度。失败的 WorkflowRun/JobExecution 保留。

- 普通主板和创业板适用；ST、退市整理、无价格限制等不适用或资料不足须明确。
- 三个基准为 SSE:000002、SZSE:399107、SZSE:399102。
- 从 2026-07-06 起连续交易日顺序构建检查点。历史更正使旧后续链失效，须顺序重算。
- 盘中次数截至上个已发布收盘；今日假设事件不写库。历史查询不用今日行情。
- 次日使用当前价假设今日收盘、指数 -2/0/+2% 情景。RPC 对已知公司行为做
  timestamped reference guard；此条件不是未来无公告的保证。已知除权或参考价不确定
  时价格为空。接口返回 reference_checked_at，页面显示校验时点。
- 无限售 A 股股本目前没有已验证的映射，盘中换手保留缺失原因；不要拿自由流通股本
  代替。确认收盘使用每日指标的换手率。换手规则本来就不能仅由价格确定。
- 官方公告覆盖未知时公告次数为空，不从计算次数或开盘啦估填。
- 价格事件链与换手历史覆盖分别记录；换手历史缺口在滚动窗口内时次数为未知，
  不因价格历史完整而显示 0。旧检查点未声明换手覆盖时保守视为未知。
- 盘中以目标交易日名称、上市/退市及上市交易日信息重新判断适用性，不继承昨日结论。
  行情时间以请求行情返回后的上海时间校验；跨日请求重新获取名单。
- 收盘回放也重新校验次日参考价。批次变更只自动恢复一次至第一页，空名单刷新重新探测。

## 只读预检

```powershell
uv run market-data-center regulation-monitor --start-date 2026-07-06 --end-date 2026-09-29
```

默认数据库会话 `default_transaction_read_only=on`。不创建批次、不补行情、不开任务。
先检查新迁移存在，否则上述命令会报告缺少数据库对象，不能绕过到旧结果。
输出交易日、缺失依赖、证券覆盖、事件/输入预期写入数量。必须查看 `can_execute`
及 PARTIAL 原因，不以命令退出成功视为全部股票完整。
`missing_dependency_details` 按交易日、股票、规则、原因稳定排序，最多展示200条；
`rule_code=null` 表示股票状态缺口，规则级缺口（包括独立换手率）保留规则编码。
`missing_detail_count` 是去重后的准确总数，`missing_details_truncated=true` 表示列表被截断。
`can_execute=true` 允许部分股票发布，不表示缺口已经补齐；预检始终只读。
每日指标 Core 仅保留一个月；历史补算可能必须先经授权 Raw 重放。禁止以零填补。

只有单独获准写入后才加 `--execute`，它先预检，再按交易日顺序发布。
相同输入复用最新批次；若该输入对应的不可变批次已经被取代，明确拒绝旧版复用，
由操作员安排新版本，不把旧批次重新标记为当前。
