# 数量单位契约、读取门禁与发布验收

依据：Accepted ADR-0068、GitHub Issue #92。代码、四个迁移和读取门禁已按后续明确授权部署，
见[生产发布记录](quantity-units-production-2026-10-23.md)。后续已获最近一个月范围授权，
事实认证/修复与剩余重算、快照及调用方缺口见[月度执行记录](quantity-units-monthly-2026-10-23.md)，不能据此宣布全历史完成。

## 单位与业务含义

| 业务字段 | 标准单位与含义 | 未认证或缺失 |
| --- | --- | --- |
| 股票日 K `volume` | 本交易日实际成交股数；100 就是 100 股，不是 100 手 | 保留价格、日期，数量为 `null` |
| 日 K / 行情金额 | 对应业务和时点的金额，人民币元；与数量独立认证 | 不由“数量已认证”推断金额已认证 |
| 买卖五档数量 | 对应方向、档位的委托股数 | 不补零，不冒称实际成交量 |
| 竞价展示量 | 展示匹配股数 | 不解释为逐笔成交或委托明细 |
| 竞价累计/序列数量 | 按 `value_semantics` / `quote_semantics` 区分指示或开盘成交 | 热表与历史归档使用同一认证规则 |
| 股本 | 对应生效日期及总股本、流通、自由流通口径的股数 | 不交换分母，不用旧已认证股本跨过较新未认证修订 |
| 可转债成交量 | 独立来源契约下的整数张 | 股票证书不能准入；成交张数证书也不能准入金额或剩余规模 |
| 指数 / THS 数量 | 独立来源契约；不推断为股票股数 | 量纲未确认时为 `null` |
| 技术因子 JSON | 每个叶子保持自己的公式和量纲 | 未认证 `obv` / `emv` / `maemv` 保留键并为 `null`，不统一乘除 100 |

来源股票 0.37 手可在有证据的 Provider 边界精确转为 37 股。Calculator、SQL 和 API 不通过价格、日期、量级推断单位，也不再次转换标准对象。显式来源 0 是可用事实；`null` 不是 0。

## 读取与部署预检

受控 SQL 迁移声明 `api_v1.quantity_unit_contract_version()`，只读返回 `stock-quantity.v1`。应用在只读事务中校验该版本；缺少函数或版本不符时不能把旧数据库响应当作已通过数量门禁的数据。它不运行迁移、采集或历史修复。

普通读取的 `quantity_quality` 包含 `unit_contract_version`、`status`、`reason` 和逐字段组的 `field_groups`。字段组的单位证据和数量覆盖是不同信息：来源明确但本来缺量的字段仍可为 `null`；调用方不得由认证状态推断所有值必定非空。

认证绑定 ingestion 与当前 Raw 哈希集合。哈希缺失、发生变化、字段组不匹配或证书隔离时，不接受旧证书。股票量额、可转债张数/金额/剩余规模、配股基准股数/募集额分别判断；一个字段组的证据不外推到其他字段。

竞价序列Raw v1是股的标准归档；v2是原生TDX手数量的包络，Provider精确转股。
已存正确事实可以经过完整尝试及热/历史副本Raw投影证明后恢复认证，操作边界见
[当日竞价恢复手册](auction-quantity-recovery-2026-10-23.md)。此路径不修改事实、
不启用通用回放，也不消除缺失/重复来源造成的partial状态。

来源单位缺失或矛盾时，新采集和 replay 记录失败批次及 ERROR 质量事实，
`details.quantity_reason` 为 `quantity_units_unverified` 或 `quantity_metadata_conflict`，
附单位契约版本；不复制原始异常值或路径。Worker 既有失败任务/质量检查据此告警，
本整改不新增下游群消息或自动通知调用方。

配股基准股数仅由 `capital.rights_issue.quantities` 认证，募集额使用独立的 `capital.rights_issue.proceeds`；两者均不能认证普通股本。派生读取先校验部署门禁，股本修订缺少认证时明确失败；配股读取仍保留价格与比例事件，不以隔离数量为由删除公司行为。

不可变日涨跌停快照仍按精确交易日选择。默认选择到未认证版本时返回现有 `deferred` 状态、空成员与明确质量原因；显式请求被拒绝的旧版本返回 `quantity_units_unverified`，SQLSTATE `PT409` 映射 HTTP 409。不会回退更早交易日，也不原地修改旧快照。

若同一原日 K 批次有任一成交量已被修复改变，引用该原批次的旧涨停复制量快照持续隔离；不能通过重新认证该批次剩余的零/空值记录使旧快照复活。修复账本保留这一依据，包括回滚后；需要按冻结输入发布新的快照版本。只依赖日 K 价格的结果不因成交量单位修复自动重跑。

PostgREST 保留其原有 `timestamptz` / ISO 日期时间语义；FastAPI 的上海墙钟展示格式不反向改变 SQL 契约。

## 分类完整性与算法版本

新计算仅使用 `1.2.0`，拒绝以旧 `1.0.0` / `1.1.0` 生成新语义结果。历史事实留存审计。

分类成员仍为所选有效快照的完整 `active.members`。任一成员整条日 K 缺失，量额各自缺失；仅缺 `volume` 不影响完整的金额合计，仅缺 `amount` 不影响完整的股数合计。`volume_member_count` 与 `amount_member_count` 独立且均不超过 `member_count`；来源 0 计入覆盖。停牌、上市/退市状态不自动剔除成员或补零。

市值覆盖、量额覆盖分别报告；市值缺失不遮蔽已完整的量额。价格、收益率、涨跌计数和原有分母保持原语义。未认证股本修订会阻断派生批次，不能通过过滤该修订回用较早股本。

## 契约与权限

- PostgREST：`contracts/postgrest-openapi-v1.json`，包含逐字段业务、单位、可空性、质量状态及只读视图字段目录。
- Agent：`contracts/agent-tools-v1.json`，输入继续严格有界、只读；`output_schema` 引用同目录 PostgREST 的响应定义。
- 技术因子对外目录为 `stock-technical-factor.v2`，同时返回 `source_factor_catalog_version=stock-technical-factor.v1`；不可变来源对象仍是 v1。
- 已补登记设计 F9 中的 8 个遗漏只读 RPC，以及最新日指标读取和部署预检。登记契约不扩大任何数据库角色权限。
- `persist_call_auction_indicative_details` 是受控写入桥接，不属于上述只读工具或公共契约。

## 验证与生产边界

有序迁移分工：`20261023000100` 声明受限证书、修复账本及备份角色只读访问；`20261023000200` 声明读取门禁和数量业务/单位注释；`20261023000300` 声明分类完整性；`20261023000400` 声明受控当前竞价写入桥接的原子认证。后者仅认证本次新建批次，不扩大桥接权限，也不把旧归档或旧批次追认为已认证。以上均是迁移文件的声明，生产是否应用仍需部署证据。

本地回归应覆盖入口精确转换、重放、独立字段组、Raw 哈希失配、量额缺失/零、分类覆盖、原批次修复后的不可变快照隔离、角色权限及契约引用。PostgreSQL 集成测试只使用通过 `TEST_DATABASE_URL` 配置的隔离可丢弃数据库。

代码发布遵循受保护迁移、独立 Raw 备份校验及服务验收；常规部署按长期规则不做 PostgreSQL 备份。
历史修复前另需全量对应 Raw 核验、冻结精确修复计划、按现有恢复规范准备依据；
受影响重算/新快照、修复前后审计与调用方签收属于后续独立操作。SQL 文件、证书结构、
脚本和本地测试通过都不代表历史操作已执行。外部消费者应确认没有额外乘除 100 的旧补偿，
并记录确认结果；不得在没有授权时代发通知。


2026-10-24技术因子例外由所有者确认：公开目录升v3，OBV/EMV/MAEMV采用独立Tushare原生指标尺度，完整返回原值，不作手股转换或声明为股/无量纲。此条替代上述技术因子null规则；quantity_quality.status=source_native，来源目录仍v1。其他领域门禁不变。
