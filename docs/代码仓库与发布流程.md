## 代码托管

- GitHub Issues 继续作为唯一任务规划记录；本次不迁移 Issue、PR、账号权限或发布凭据。

初次克隆后配置镜像：

```bash
git clone https://gitee.com/guokaige/data_center.git
cd data_center
git remote add github https://github.com/yuexing89757/data_center.git
```

迁移核验：通过独立 `--mirror` 克隆逐一比较分支/标签引用并执行 `git fsck`。

## 日常提交与发布

继续按 AGENTS.md 直接在 `master` 开发。普通代码推送使用：

```bash
git push origin master
```

需要触发现有 CI 或发布时，同步同一提交到 GitHub：

```bash
git push github master
```

`.github/workflows/ci.yml` 仍在 GitHub 运行，包括隔离 PostgreSQL migration/集成测试。
`.github/workflows/production.yml` 的 production 环境、受保护流程与原有凭据保持不变。
Gitee 代码同步本身不会触发 GitHub Actions，不能把推送 Gitee 当作 CI 或生产迁移成功。

生产 Schema 仍只能通过现有 `Production migration and smoke check` 执行；
发布前确认所选提交已在 GitHub、CI 已通过，再按已授权窗口执行 check/apply。
不在 Gitee 新建存有生产密钥的流水线，不通过手工 DDL 绕过保护流程。
GitHub 不可用时，可以继续在 Gitee 保存代码，但须保留原生产发布门禁并明确报告阻塞。
