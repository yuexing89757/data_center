# 开盘啦竞价实时接口

## 接入状态

统一接入现有 FastAPI，Swagger 分类“实时接口”，复用 `X-API-Key`、Pydantic、统一错误格式
和中文 OpenAPI。请求时获取一页，不读写数据库、不保存 Raw、不触发 Worker。
不需要数据库迁移，更新代码后重启现有 API 服务即可；本次未重启服务。

**历史竞价已验证可用；当前 HTTP 查询尚不可用。** 2026-09-27 实测当前接口返回整行
`kaipanla.com` 占位值，适配器返回 502，绝不会当作股票或成功空列表。APP 当日使用的
TLS Socket/Protobuf 命令 2103 尚未接入。不能据此接口宣称已经具备盘中竞价实时流。

这里的“实时接口”是请求时直连、不入库的分类；历史查询仍然读取指定日期。

## 请求

```text
GET /api/v1/realtime/kaipanla/auction-pool
X-API-Key: <现有服务 API key>
```

|参数|类型/默认值|规则|
|---|---|---|
|`trade_date`|可选日期|`YYYY-MM-DD`；传入走历史 HTTP，省略走当前 HTTP；拒绝上海时区未来日期|
|`offset`|整数，0|记录偏移，范围 0–10000|
|`limit`|整数，30|每页 1–30 条；不能传 200，来源曾因此返回伪空列表|
|`exclude_st`|布尔，true|是否过滤 ST；适配器内部转成来源 `Is_st`|

固定按涨停委买额降序，不开放尚未验证的其他排序或板块筛选参数。

```bash
curl -H "X-API-Key: $FASTAPI_API_KEY" \
  "http://127.0.0.1:8000/api/v1/realtime/kaipanla/auction-pool?trade_date=2026-09-24&offset=0&limit=30&exclude_st=true"
```

## 响应

|字段|含义|
|---|---|
|`source_code`|固定 `kaipanla`|
|`pool_scope`|固定 `kaipanla_auction_pool`，是开盘啦“打板→竞价池”，不是全市场或旧伯乐候选池|
|`persisted`|固定 false|
|`query_mode`|`history` 或 `current`|
|`requested_date`|调用方日期；当前查询为空|
|`trade_date`|来源实际日期；历史不匹配直接报 502，不返回其他日期替代|
|`observed_at`|收到响应的上海时间 `YYYY-MM-DD HH:mm:ss`，不是行情发生时点|
|`exclude_st`|回显 ST 过滤条件|
|`offset / limit / returned_count`|本页偏移、页长、本页实际条数|
|`total`|固定 null，来源没有可靠总数|
|`next_offset`|满页时提示继续请求；不足一页或达到偏移上限则为 null；满页不保证还有下一页|
|`sort_by / sort_order`|固定 `limit_up_bid_amount_cny` / `desc`|
|`items`|规范化股票记录|

### 股票字段及单位

所有小数使用 Decimal，对外以 JSON 字符串返回。零与 null 不混用；来源 `null`、空字符串、
`--` 数字占位转为 null；非法数字或结构错误返回 502，不自行补零。

|字段|来源下标|含义/单位|
|---|---:|---|
|`symbol`|由代码构造|标准证券代码，如 `SSE:600825`|
|`code`|0|六位字符串，保留前导零|
|`name`|1|名称|
|`change_pct`|4|普通行情涨跌幅，百分比，与竞价涨幅不同|
|`board_name`|11|来源板块/题材文字，不等于数据中心标准分类|
|`actual_float_market_value_cny`|15|来源“实际流通”金额，元；不是流通股数|
|`limit_up_bid_amount_cny`|18|涨停委买额，元；不是竞价成交额|
|`auction_change_pct`|19|竞价涨跌幅，百分比；10.0567 表示 10.0567%|
|`auction_net_amount_cny`|20|竞价净额，元，允许负值|
|`auction_turnover_rate_pct`|21|竞价换手率，百分比；0.23 表示 0.23%|
|`auction_amount_cny`|22|竞价成交额，元|

下标来自 APP 6.3.20.0 的 `PatternDynamicQuota` 和页面交叉核对，不使用其他竞价页面
`MorningBiddingDynamicQuota` 的布局。只提供已确认的有名字段，不对外返回下标数组。

## 分页与一致性

一次 FastAPI 请求只请求上游一次。不自动翻页，也不自动重试。用相同日期、过滤条件和页长，
沿 `next_offset` 读取，直到 null；消费者跨页按 code 去重并核对日期。来源可能变化，不提供
跨请求不可变快照保证。默认页长 30，取 127 条需要五页。全量与历史回放应由消费者明确发起。

历史路由：POST `apphis.kaipanla.com/w1/api/index.php`，`HisHomeDingPan/HisDaBanList`，
参数 `Day`、`Index`、`st`、`Is_st`，固定 `PidType=8, Type=18, Order=1`。
当前路由：POST `apphwshhq.kaipanla.com/w1/api/index.php`，`HomeDingPan/DaBanList`。
来源域名、方法和其他参数固定，调用方不能指定任意 URL/action，也不需要提交来源登录凭据。

## 错误与配置

- 401：缺少或错误的 API key。
- 422：非法日期、未来日期、分页或布尔参数。
- 502 `upstream_error`：网络失败、超时、业务失败、占位响应、日期错位、重复代码、行结构或数值错误。
- 只有日期有效且明确成功的空列表才返回 200 空页。

错误形状：

```json
{"error":{"code":"upstream_error","message":"Kaipanla auction provider request failed"}}
```

复用 `FASTAPI_KAIPANLA_TIMEOUT_SECONDS=8`，范围 1–10 秒，为网络操作超时而非全请求 SLA。
单响应最大 2 MB，不跟随重定向，不使用系统 HTTP 代理，不读取或写入数据中心数据库。
现有 API 应用启动仍要求既有数据库配置，竞价请求路径本身不调用数据库。
