# 883423 板块日线 Worker 收盘采集设计

## 范围

本设计落实 Issue #60 与 ADR-0043，只处理固定板块 `THS:883423`。不扩展为任意
板块代理，不改变普通股票日线 Provider 路由，也不增加操作系统级定时任务。

## 数据流

1. APScheduler 在 Worker 内于工作日 15:30、16:30、17:30 触发同一任务。
2. 回调从交易日历解析最近应有交易日，并比较数据库最新 `THS:883423` 日线。
3. 已覆盖目标日期时记录成功的幂等空操作；有缺口时调用现有 BoardIndex 日线
   Pipeline，采集缺失区间。
4. Pipeline 依次完成 Provider 适配、Raw 保存、校验、IngestionRun 及 Core 幂等写入。
5. FastAPI 始终通过 `api_v1.query_board_index_bias_latest()` 读取最多 34 条事实并计算。

## 调度与重试

- 三个收盘时点固化在任务目录，使用一个任务标识和同一执行回调。
- 单轮最多请求三次，重试间隔固定且有界；不使用无限重试。
- 只有可重试的外部 Provider 故障进入下一次尝试。数据校验、持久化和约束错误立即失败。
- 后续时点重新执行相同幂等判断；已采集成功就跳过，仍有缺口才再次请求。
- 下一交易日以数据库最新日期为起点继续补采，因此覆盖上一日最终失败的情况。

## 查询与错误

- 数据库至少有 34 条记录：返回最新存储交易日的计算结果和真实 `trade_date`。
- 数据少于 34 条或完全为空：RPC 抛出 `P0002`，FastAPI 返回 404。
- 数据库超时或其他错误：保持数据库错误映射，不访问外部 Provider。
- Provider 失败只影响 Worker 执行记录，不改变 API 请求路径。

## 安全与权限

- FastAPI 角色仅保留查询 RPC 执行权限。
- migration 撤销并删除实时持久化 RPC，避免残留 API 写通道。
- 数据库地址、Provider 凭据和调度时间不进入公共契约或日志。

## 测试边界

- 调度目录：三个固定时点、默认启用、禁用开关、工作日表达式。
- Worker 回调：最新日期跳过、缺口范围、三次重试、成功停止、最终失败。
- API：数据库命中、旧日期仍返回、历史不足 404、数据库错误不触发 Provider。
- PostgreSQL：查询 RPC 新鲜度语义、写 RPC 不存在/无权限、workflow code 约束。
- 契约：FastAPI OpenAPI 与处理器响应保持同步。
