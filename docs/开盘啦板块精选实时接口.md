# 开盘啦板块精选实时接口

更新：2026-10-26。依据 ADR-0059 的实时只读增补，已集成到现有 `market-data-api`。
Swagger 分类为 **实时接口**，业务请求统一要求 `X-API-Key`。

此处“实时接口”表示请求时直连上游，也包括按日期读取历史数据。排行每次仅请求一页，成员有界收集完整列表，不写数据库、
不保存Raw、不触发Worker，不使用数据库或其他日期兜底。没有新增数据库迁移或依赖。

## 2026-10-26 成员全局排序变更（Issue #99）

成员接口先有界收集整个板块，再按来源龙一至龙十、其余涨幅降序排序，最后按offset/limit分页。
同名次按涨幅降序、同值按代码升序，缺失涨幅末尾。仅精确龙一至龙十享有优先级。
最多6000条、101次来源请求、累计8 MiB及10秒内的配置总时限；任一页失败整次502。
跨页核对日期、代码唯一性、预测年份和TLS总数；不返回部分结果。
成员next_offset依据完整列表是否仍有剩余项，total继续null，无跨请求快照隔离。
该变更只影响成员查询，排行接口不受影响。

## 1. 三个路由

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/v1/realtime/kaipanla/boards` | 最新板块排行 |
| GET | `/api/v1/realtime/kaipanla/boards/history` | 指定日期板块排行 |
| GET | `/api/v1/realtime/kaipanla/boards/{board_code}/members/history` | 指定日期成分股（含当天），含机构预测 |

| 参数 | 规则 |
| --- | --- |
| `board_code` | 成员路由必填路径参数，六位开盘啦板块代码，例如`803023`；不是股票symbol |
| `trade_date` | 两个指定日期路由必填查询参数，`YYYY-MM-DD`；均不允许未来日期 |
| `offset` | 三个路由均支持，默认0，范围0～10000；记录偏移，不是页号 |
| `limit` | 三个路由均支持，默认60，范围1～60 |

最新接口返回来源实际日期，闭市时可以是最近交易日。历史接口要求响应日期严格等于请求日期；
不将请求日期填充为来源日期，不自动改查上一交易日。休市历史请求如果返回其他日期，会返回502。

指定上海当天的板块排行使用最新行情源，过去日期使用历史源；上游历史源不提供当天排行。
当天查询仍保持`query_mode=history`以及请求日期，严格核对来源`Day`；最新源尚未更新到当天时
仍返回502，不返回上一交易日数据。该路由规则在请求前确定，不是失败后的重试或回退。

成员查询传上海当天时使用TLS命令2501，过去日期仍走HTTP；当天是当前快照，不代表收盘终值。
来源日期尚未更新到当天时返回502，不以昨天的数据替代。`query_mode`保持`history`，表示指定日期查询。
子题材、消息、日线及RPS未在本次接入范围。

## 2. 标准响应

| 字段 | 含义 |
| --- | --- |
| `source_code` | 固定`kaipanla` |
| `persisted` | 固定`false`，本次结果是临时上游观察 |
| `query_mode` | `latest`或`history` |
| `requested_date` | 请求日期；最新查询为null |
| `trade_date` | 验证后的来源实际行情日期 |
| `observed_at` | 本服务取得响应的上海时间，`YYYY-MM-DD HH:mm:ss`；不等于行情更新时间 |
| `offset / limit` | 本页偏移与请求页长 |
| `returned_count` | 实际返回行数 |
| `total` | 固定null；来源Count可能仅为本页数量，不能视为总量 |
| `next_offset` | 排行满页提示下一偏移；成员仅在完整排序列表有剩余时返回下一偏移，否则null |
| `items` | 规范化记录；排行保持来源顺序，成员按全局排序后分页 |

成员响应额外提供`board_code`与`forecast_years`（已确认的三个年份，无法核实时为空数组）。
小数统一以JSON字符串返回，整数仍为整数，未知值为null。金额单位均为人民币元，百分数
`"5.97"`表示5.97%，无需再乘100。

### 分页注意

- 排行请求只访问一次上游；成员从来源offset=0开始按60条收集完整列表，排序后按公共offset/limit切片。
- 排行next_offset只表示可继续尝试；成员依据本次完整列表计算next_offset，末页恰好满页时也为null。
- 校验页长和日期；成员额外校验跨页重复代码、预测年份及TLS总数，异常整次失败。
- 独立分页不提供快照隔离。来源排序变化可能造成跨页重复或遗漏；消费者应核对每页日期和
  唯一代码。最新排行可先读取trade_date，再选择相应历史排行路由固定日期，仍须验证上游返回。
- 成员分页时还需核对每页forecast_years一致，避免把不同年份的预测拼接。

## 3. 板块排行字段

| 返回字段 | 含义 | 上游数组下标（0起） |
| --- | --- | --- |
| board_code / name | 板块代码 / 名称 | 0 / 1 |
| strength | 来源强度，非数据中心计算 | 2 |
| change_pct / change_speed_pct | 涨幅 / 来源涨速，百分比；涨速窗口未披露 | 3 / 4 |
| amount_cny | 成交额，元 | 5 |
| main_net_amount_cny | 主力净额，元，可负 | 6 |
| volume_ratio | 量比，倍数 | 9 |
| large_order_net_amount_cny | 大单净额，元，可负 | 12 |

板块名称、强度仅转述来源，不将其映射为内部标准分类或交易判断。

| concept | 来源概念原文 | 4 |
| last_price / change_pct | 所选日价格，元 / 涨幅，百分比 | 5 / 6 |
| amount_cny / actual_float_market_value_cny | 成交额 / 实际流通市值，元 | 7 / 10 |
| main_buy_amount_cny / main_sell_amount_cny / main_net_amount_cny | 主力买 / 主力卖 / 主力净额，元；卖出保留来源负号 | 11 / 12 / 13 |
| buy_share_pct / sell_share_pct | 买占比 / 卖占比，百分比 | 17 / 18 |
| volume_ratio | 量比，倍数 | 21 |
| height_label / leader_label | 高度 / 龙头原文，不删除文字或转为本系统策略 | 23 / 24 |
| close_limit_bid_amount_cny / max_limit_bid_amount_cny | 收盘封单 / 最大封单，元 | 28 / 29 |
| total_market_value_cny / float_market_value_cny | 总市值 / 流通市值，元 | 37 / 38 |
| leading_count | 领涨次数，非负整数 | 40 |
| large_order_net_amount_cny | 大单净额，元 | 50 |
| profit_forecasts | 按年份组织的净利润预测 | 44 / 45 / 46及ZB标签 |
| forecast_status | 预测可用性说明，见下文 | 标签与预测值校验结果 |

股票代码路由：6开头为`SSE`，0/3开头为`SZSE`，4/8/9开头为`BSE`，其他前缀拒绝。
价格、成交额、市值、封单等不允许负值；主力净额、卖出额、大单净额和预测利润允许负值。

### 预测年份与零值

从来源`ZB`中提取形如`2026年预测净利润`的标签，必须有三个唯一、递增的年份，按顺序对应
44/45/46列；`2025年实际净利润`不参与预测映射，年份不会写死。

```json
{
  "forecast_status": "available",
  "profit_forecasts": [
    {"year": 2026, "net_profit_cny": "1042823529.123456789"},
    {"year": 2027, "net_profit_cny": "-20"},
    {"year": 2028, "net_profit_cny": "0"}
  ]
}
```

这是结构示例，不是真实个股财务数据。

- `available`：年份已确认，至少一项预测非零且非缺失；部分缺失仍为null。
- `not_provided`：年份已确认，但三项均为零或缺失。来源使用三零表示没有机构预测；仍保留原始
  零与null差异，消费者不可把这组三零解释成确切的零利润预测。
- `years_unverified`：未取得恰好三个预测年份，`forecast_years=[]`、`profit_forecasts=[]`，不猜测年份。
- 标签结构损坏或三个年份重复/乱序返回502，不悄悄改变顺序。后续可选数值列缺失时留null；
  必需身份列/基本行情行不足25项则整页失败。

## 5. 上游请求映射

HTTP使用固定GET端点，当天成员使用固定TLS端点；不接受调用方提供URL或地址，
未发送开盘啦账号、token、Cookie或设备凭据。

| 路由 | 固定上游域名 | a | apiv |
| --- | --- | --- | --- |
| 最新排行 | `apphq.longhuvip.com` | `RealRankingInfo` | w21 |
| 指定过去日期排行 | `apphis.longhuvip.com` | `RealRankingInfo` | w26 |
| 指定上海当天排行 | `apphq.longhuvip.com` | `RealRankingInfo` | w21 |
| 历史成员 | `apphis.longhuvip.com` | `ZhiShuStockList_W8` | w41 |

以上HTTP路径均为`https://<域名>/w1/api/index.php`。公共参数：

```text
c=ZhiShuRanking    Order=1    Type=1    PhoneOSNew=1    VerSion=5
Index=<offset>    st=<limit>
```

排行附加`ZSType=7`；过去日期附加`Date=trade_date`，当天排行不发送`Date`；历史成员附加
`PlateID=board_code、IsZZ=0、IsKZZType=0、filterType=0、TSZB=0、TSZB_Type=0`。
UA使用已核实的`Dalvik/2.1.0 (Linux; U; Android 6.0.1; MuMu Build/V417IR)`。

上游必须`errcode=0`，`Day`可为单个日期字符串或仅含一个日期的数组，`list`必须是数组。
JSON小数在解码时直接采用Decimal；未知数组列不对外透传，不使用未验证的字段猜测。

### 当天成员TLS

固定连接`124.71.166.244:14000`，SNI为`apphwshhq.kaipanla.com`，命令2501。
使用包内公开证书`providers/certificates/kpl-quote.pem`验证服务器，保留主机名校验；
证书过期或变更导致失败时应通过核查后发版更新信任材料，禁止自动信任或关闭验证。
完整连接、握手、发送、心跳和响应读取共享一个超时预算，不因分段读取重置。
响应body上限65535字节，最多允许8个前置心跳，字段数量有界；不会无限等待行情流。

校验命令/描述符、板块、日期、偏移、来源总数、精确页长、行索引和代码目录；
空页须由来源总数及明确日期共同证明。数据转换后复用HTTP成员的Decimal、字段及预测标签校验。
协议布局和已验证分页边界详见[核查记录](runbooks/guanchao-platepick-api-analysis-2026-10-26.md)。

## 6. 鉴权、错误与运行

| HTTP状态 | error.code | 条件 |
| --- | --- | --- |
| 401 | unauthorized | 缺少或错误的X-API-Key |
| 422 | validation_error | 日期、代码或分页参数不合法；请求未来日期 |
| 502 | upstream_error | 网络/超时/证书失败/非JSON/业务失败、缺日期、日期不符、重复股票、非法数值或帧结构 |

502统一格式：

```json
{"error":{"code":"upstream_error","message":"Kaipanla board provider request failed"}}
```

错误不输出上游原文或地址细节。只有成功且含明确空list的响应才返回200空列表。

复用`FASTAPI_KAIPANLA_TIMEOUT_SECONDS`，默认8秒、配置范围1～10秒，是网络操作超时；响应最大
2 MB（HTTP）；当天TLS使用同一配置作为完整请求总预算，单帧最多65535字节。
不重试、不跟随重定向、不使用系统HTTP代理。服务启动仍遵循现有API Key和数据库连接
配置，但这三个请求路径不读写数据库，不新增环境变量。

启动现有应用：`uv run market-data-api`，在`/docs`的“实时接口”中测试。PowerShell示例：

```powershell
$headers = @{ 'X-API-Key' = $env:FASTAPI_API_KEY }
$base = 'http://127.0.0.1:8000/api/v1/realtime/kaipanla/boards'
Invoke-RestMethod -Headers $headers -Uri "$base`?offset=0&limit=60"
Invoke-RestMethod -Headers $headers -Uri "$base/history?trade_date=2026-09-28&offset=0&limit=60"
Invoke-RestMethod -Headers $headers -Uri "$base/803023/members/history?trade_date=2026-09-28&offset=0&limit=60"
```

代码接入后需重新启动或部署API进程才会对外生效；各次部署结果以发布验收记录为准。
