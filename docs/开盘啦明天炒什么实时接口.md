# 开盘啦“明天炒什么”最新列表实时接口

`GET /api/v1/realtime/kaipanla/hot-talks`，需要 `X-API-Key`，Swagger 分类“实时接口”。
读取 App 首页最新主题上方图片入口“明天炒什么 → 查看全部”的最新日期全部条目。
盘中入口可能显示“今天炒什么”，两者为同一来源列表。

每次请求直接访问固定上游一次，没有查询参数，不使用模拟器、账户凭据或静态导出文件。
不自动重试、翻页、回退或请求详情；不写数据库/Raw，不注册 Worker 任务。
复用 `FASTAPI_KAIPANLA_TIMEOUT_SECONDS`（默认8秒，上限10秒）、2 MB响应上限、
禁止重定向和系统代理。不开放可变上游地址或 action。

## 响应

| 字段 | 含义 |
| --- | --- |
| source_code | 固定 kaipanla |
| source_layout | 固定 kaipanla.hot_talks.v1 |
| persisted | 固定 false |
| observed_at | 本服务收到响应的上海时间 |
| topic_date | 来源最新日期分组；不保证是交易日或今天；成功空列表为 null |
| returned_count | 最新日期的条目数，上限100 |
| items[].topic_id | 来源条目 ID |
| items[].rank | 最新日期组内来源展示顺序，从1开始 |
| items[].title | 来源标题，不包含 UI 附加的投票标记 |
| items[].heat_value | HotVal，页面热度值的精确整数；不推断为阅读人数；缺失为 null |
| items[].published_at | 来源 Time（Unix秒）转上海时间；可能与分组日期不同；缺失为 null |
| items[].has_vote | 来源 IsVote 标记是否包含投票；不读取选项、不提交投票 |

时间使用 `YYYY-MM-DD HH:mm:ss`，没有时区后缀和小数秒。
热度会变化，来源计算规则未公开；不把“万”单位显示文本当成精确计数或阅读人数。
来源标题是第三方信息，不作为数据中心策略或交易建议。
明确成功的空列表返回200；最新组为空时保留该日期，不选择较旧的非空组。

## 验证与错误

2026-10-10 从 App 6.3.20.0 的运行代码核实 `Topic/InfoList`，固定上游为
`https://applhb.kaipanla.com/w1/api/index.php`，POST 参数
`c=Topic&a=InfoList&Index=0&st=20`。无 UserID、Token 或其他登录参数的请求成功。
只向消费者返回首个最新组；日期必须严格倒序、有效且不晚于上海今天。
该固定请求的实际日期组数量最多21，每组上限100条；超限不截断为成功。
最新日期2026-10-08的两条 ID、标题与 MuMu 页面一致。
App 通用请求附带账号字段不代表此列表需要登录；此前 UI 工具的登录限制说明已修正。

缺少/错误 API key 返回401。来源失败、非JSON、结构错误、非法计数/标记/时间、重复ID、
错乱日期或超限返回502 `upstream_error`，不泄露来源正文或内部错误。
