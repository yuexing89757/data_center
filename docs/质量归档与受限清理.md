# 质量归档与受限清理（ADR-0058 子集）

2026-09-27：本地实现，待验收与单独授权生产迁移、部署；不是整个存储生命周期计划已交付。

## 范围

`data-cleanup-daily` 仍由 Worker 每天上海时间 03:00 执行。竞价在线三个已完成交易日、历史六个月的
保留规则不变。原有“超过30天无归档删除所有 quality_result”的入口现已拒绝执行。

新增步骤 `archive_auction_quality` 仅处理 `call_auction_market_series` 的
`realtime_quote.lot_precision` INFO、`realtime_quote.missing_source_timestamp` WARNING。
要求采集终态、未带 aggregation_version、整个 ingestion/rule 组的最后创建时间严格早于执行日上海零点减30日。
ERROR、其他数据集/规则、在线汇总不删除；失败及部分成功采集批次的合格明细也保存原有状态，不伪装成功。

全字段 PostgreSQL JSON 文本按质量 ID 排序保存到
`_quality_archive/<ingestion_id>/<rule_code>/<content_sha256>.jsonl.gz`。
不经 float 重新编码。固定 gzip mtime，独占临时文件，no-replace 发布，完整校验压缩及内容 SHA、字节数、
字段、创建时间和精确 ID；文件与目录 fsync 成功后才允许提交数据库事务（Windows 无目录 fsync）。

事务锁住父 IngestionRun（复用 Worker 已有权限，不扩大质量表 UPDATE 权限），重读并比对全字段，
登记 `audit.quality_archive`，按状态/消息分组写入全部 affected_keys、finding_count 和 archive_id，
再删除精确 ID。DELETE RETURNING 全字段再比对；任何变化回滚登记、汇总和删除。文件发布后数据库失败，
原记录保留，下次可校验复用同一文件。已归档组再次提交不新增、不删除。

RLS 替换旧的 permissive ALL 策略，DELETE 只允许满足白名单、期限、终态和归档精确 ID 的记录。
数据库不能验证外部文件字节，因此 RLS 是额外防线，不能替代应用的完整文件校验。
Worker 对归档只有 SELECT/INSERT；API、anon、authenticated 无归档和维护报告权限。

## 运行与保护

```text
uv run market-data-center data-cleanup
uv run market-data-center quality-archive-inspect --ingestion-id <UUID>
# 以下只有得到本次执行授权后才可运行：
uv run market-data-center data-cleanup --execute --confirm
```

默认预览只读数据库及磁盘容量，不创建目录、运行记录、报告、临时文件，不获取写锁、不删除。
输出包含快照截止日/数量/缺归档数、质量候选组与行数、容量；核验命令只输出数量及哈希，不泄漏来源内容。
执行双标志缺一返回2；部分完成/失败返回1，成功返回0。没有任意路径/表名/保留期参数。

自动任务仅在实际上海时间 [03:00,04:00) 开始，延迟越界记录 partial，不删除。
手工执行避开 [09:10,09:40)，截止不超过下一09:10；共同使用 `maintenance:data_cleanup` 单实例锁。
最多30分钟，每次最多100,000条旧明细、每页200组、每组最多256 MiB，不拆分跨截止组或超限组。
每个维护 SQL 事务 lock_timeout=2s、statement_timeout=30s；预算是协作式，不保证硬中断文件系统阻塞。
已成功单元不因之后的预算、坏文件等故障伪装回滚；错误组保留，独立组继续，任务显式 partial。
数据库不可用、锁丢失、磁盘不足则停止新写入。

写入前至少有512 MiB，且满足两倍原文加1 MiB的空间要求；80%警告，90%或不足2 GiB严重告警。
`operations.data_cleanup_report` 保存截止点、行数、归档字节数、剩余候选、容量、错误码及临时文件归属。
临时文件写前登记；中断遗留文件不自动猜测删除。本子集不实现 Raw 压缩、通用临时清理、旧发布物清理，
也不改变新采集质量记录的构造方式，这些仍在原计划待实施。

## 发布、备份与回退

必须先执行受保护有序迁移 `20260927000100_restrict_quality_cleanup.sql` 再部署 Worker；迁移自身不删除数据。
迁移会为白名单明细建立部分索引；上线前测量磁盘余量并安排非采集维护窗口，建索引需要额外空间且可能阻塞写入。
本地实现不代表已授权生产首次清理。生产首次执行前须确认归档根可写，数据库和文件备份均覆盖新增元数据和
`_quality_archive`。仅恢复数据库会丢失归档明细，不能声称完整恢复；恢复后逐 ingestion 核验归档。
应用回退不得移除归档文件或放宽 RLS，旧版直接删除入口会被限制，不能回滚到无归档删除语义。

数据库 DELETE 只产生可复用空间，不承诺立即归还操作系统磁盘；Worker 不执行 DDL、VACUUM FULL 或表重写。
