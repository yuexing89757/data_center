# Worker 任务时间代码化设计

日期：2026-08-11
状态：Accepted
关联 Issue：#40

## 1. 背景与目标

Worker 的任务定义已经由受控代码目录统一注册，但任务执行时间、采样节奏和部分恢复参数仍可
通过 `.env` 覆盖。这会使服务器实际调度与仓库代码、运行手册和测试产生差异。

本变更把任务时间与调度策略收回代码目录：`.env` 只允许控制现有可选任务的启用或停用，
不再配置任务执行时间。集合竞价五档和收盘五档在没有环境覆盖时默认启用；今日竞价量固定在
工作日 21:30 执行，并且只处理当日涨停池成员。

## 2. 配置边界

### 2.1 `.env` 允许保留的任务开关

- `AUCTION_COLLECTION_ENABLED`，默认 `true`；
- `EOD_QUOTE_SNAPSHOT_ENABLED`，默认 `true`；
- `CALL_AUCTION_SNAPSHOT_ENABLED`，默认 `true`。

这些布尔开关只决定对应任务是否注册。现有始终启用的基础任务不新增环境开关。

### 2.2 仍属于运行环境的配置

- `SCHEDULER_STORE_PATH`：APScheduler 本地持久化路径；
- `WORKER_ADMIN_PORT`：本地只读管理页端口；
- `PYTDX_POOL_PATH`：统一 PYTDX 节点池的持久化路径。

这些值不定义某个任务的执行时间，因此继续保留在环境配置中。

### 2.3 从环境配置中移除的内容

- 所有任务的 hour/minute 字段；
- scheduler 时区，固定为 `Asia/Shanghai`；
- 集合竞价五档的内部采样节奏；
- PYTDX 节点池刷新间隔；
- stale recovery 间隔与 misfire/timeout 策略。

旧环境变量继续由 Pydantic 的 `extra="ignore"` 安全忽略，但不再改变任务目录。部署模板、安装
文档和运行手册不再指导配置这些变量。

## 3. 代码目录中的固定计划

| 任务 | 固定计划 | 默认状态 |
|---|---|---|
| 集合竞价涨停池五档采集 | 工作日 09:15，内部每 5 秒采样至 09:25 | 启用 |
| 今日竞价量 | 工作日 21:30 | 启用 |
| 日 K 与基础数据更新 | 工作日 20:00 | 启用 |
| 股票每日指标更新 | 工作日 20:30 | 启用 |
| 沪深主板昨日涨跌停股票池 | 工作日 21:00 | 启用 |
| 收盘五档快照 | 工作日 21:10 | 启用 |
| 扣非净利润增量同步 | 每天 20:00 | 启用 |
| 陈旧运行恢复 | 每 1 小时 | 启用 |
| PYTDX 节点池刷新 | 每 12 小时，并在 Worker 启动时先刷新 | 启用 |

misfire 宽限和 job timeout 固定为 21,600 秒。任务目录继续是 scheduler 注册、operations
workflow、健康检查和本地只读管理页的共同事实来源。

## 4. 今日竞价量的数据范围

`collect_call_auction` 继续通过精确交易日的涨停池查询取得证券列表：

- 只读取涨停池，不读取跌停池；
- 不使用旧交易日股票池回退；
- 当日涨停池为空时合法跳过；
- 保存当日集合竞价量、额和溢价率，并保留 Raw、质量与 ingestion lineage；
- 21:30 只改变任务触发时间，不改变领域记录、持久化表或公开读取契约。

## 5. 实现边界

`SchedulerSettings` 只保留持久化路径、本地管理端口和三个可选任务开关。固定时区、cron、
interval、cadence、misfire 和 timeout 值集中在 `scheduling_catalog.py`，避免散落到 scheduler
执行函数。执行函数需要计算业务交易日时，应读取对应 `JobDefinition` 的固定计划，而不是
重新从环境设置读取 hour/minute。

`PytdxPoolSettings` 只保留节点池路径；12 小时刷新间隔归任务目录所有。不会增加 cron、systemd
timer、Windows Task Scheduler 或其他操作系统级触发器。

## 6. 部署与兼容性

`.env.example` 和 Linux 生产模板删除所有任务时间变量，只展示三个启停开关。两个五档任务的
模板值和代码默认值均为 `true`。已有服务器即使暂时残留旧时间变量，新版本也会忽略它们；
运维应在发布时删除这些无效变量，避免误解。

本变更不需要 SQL migration，不改变 Raw/Core/derived/realtime schema，也不改变 PostgREST、
FastAPI 或 agent-tools 公共契约。生产发布、Worker 重启和任务状态核对仍需单独明确授权。

## 7. 测试与验收

- 设置测试证明三个开关默认启用且仍可由环境布尔值停用；
- 调度目录测试逐项断言固定计划，尤其今日竞价量为工作日 21:30；
- 环境隔离测试设置旧 hour/minute/refresh 变量后，任务计划仍保持代码值；
- 今日竞价量采集测试证明输入证券只来自精确交易日涨停池；
- 生产检查证明环境模板不包含任务执行时间变量，只包含允许的启停开关；
- Ruff、mypy、全量 pytest 通过；PostgreSQL integration 只使用 disposable
  `TEST_DATABASE_URL`；公共契约文件保持无差异。

## 8. 成功标准

- 删除 `.env` 中所有任务时间配置后，Worker 仍按代码目录的固定计划注册任务；
- 集合竞价五档与收盘五档在无环境开关时显示启用；
- 今日竞价量在管理页显示工作日 21:30，且只采集当日涨停池；
- `.env` 对任务的唯一可变能力是三个现有布尔启停开关；
- 没有新增操作系统级调度、数据库变更或公共 API 变化。
