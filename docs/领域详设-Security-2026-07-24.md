# 领域详设：Security v2

> 状态：第一阶段有效  
> 修订日期：2026-07-27  
> 依据：`adr/ADR-0001-第一阶段架构基线.md`

## 1. 领域职责

Security 是证券身份和低频生命周期的权威来源，回答：市场上有哪些证券、它们的统一身份是什么、何时上市或退市、当前使用什么名称。

Security 不保存行情、停牌日状态、分类、股本、估值或主观标签。

## 2. 统一标识

```text
SSE:600000
SZSE:000001
BSE:920000
```

- `exchange`：`SSE`、`SZSE`、`BSE`；
- `code`：保留前导零的证券代码；
- `symbol = exchange + ':' + code`；
- `symbol` 是跨领域唯一关联键；
- BaoStock 的 `sh.600000` 等来源代码只存在于 Provider 和 Raw 中。

## 3. 实体：Security

数据库表：`core.security`

| 字段 | 类型 | 约束与含义 |
| --- | --- | --- |
| `symbol` | text | 主键，统一标识 |
| `code` | text | 非空，保留前导零 |
| `exchange` | text | 非空，受控枚举 |
| `current_name` | text | 当前名称，非空 |
| `security_type` | text | `stock`、`index`、`other`、`convertible_bond`、`etf`、`unknown` |
| `status` | text | `listed`、`delisted`、`unknown` |
| `ipo_date` | date | 可空 |
| `delisting_date` | date | 可空 |
| `source_code` | text | 标准来源标识，第一阶段为 `baostock` |
| `ingestion_id` | uuid | 外键关联采集批次 |
| `created_at` | timestamptz | 创建时间 |
| `updated_at` | timestamptz | 最近更新时间 |

约束：

- `unique(exchange, code)`；
- `delisting_date >= ipo_date`（两者均存在时）；
- `status = 'delisted'` 时原则上应存在 `delisting_date`，来源暂缺时进入质量告警；
- 停牌不允许写入 `status`。

## 4. 实体：SecurityNameHistory

数据库表：`core.security_name_history`

| 字段 | 类型 | 约束与含义 |
| --- | --- | --- |
| `symbol` | text | 外键关联 Security |
| `name` | text | 证券名称 |
| `effective_from` | date | 生效日期 |
| `effective_to` | date | 失效日期，当前名称为空 |
| `source_code` | text | 标准来源标识 |
| `ingestion_id` | uuid | 采集批次 |

主键：`(symbol, effective_from)`。

同一 `symbol` 的有效区间不得重叠。若来源只有当前名称且无法确定生效日，第一阶段以采集日作为 `effective_from`，同时记录质量提示，不伪造历史。

## 5. 标准 DTO

```text
SecurityRecord
├── symbol
├── code
├── exchange
├── name
├── security_type
├── status
├── ipo_date
├── delisting_date
└── source_code
```

DTO 不包含来源字段名、完整 Raw 响应或 `ingestion_id`。Pipeline 使用 `IngestionEnvelope[SecurityRecord]` 附加批次 ID。

## 6. 幂等与更新

- 按 `symbol` upsert 当前快照；
- 身份字段冲突不得静默覆盖，写入质量结果；
- 名称变化关闭上一有效区间并插入新记录；
- 同一采集批次重跑不得生成重复名称历史；
- 已退市证券保留，不做物理删除。

## 7. 校验

- `symbol` 与 `exchange/code` 一致；
- 代码前导零未丢失；
- 日期顺序合法；
- 名称非空；
- 枚举属于允许集合；
- 同批次不存在重复 `symbol`。

## 8. API 契约

`api_v1.securities` 只读 View 第一阶段公开：

```text
symbol, code, exchange, current_name,
security_type, status, ipo_date, delisting_date
```

不公开 `ingestion_id`、内部时间戳和质量信息。

## 9. 第一阶段验收

- BaoStock 代码可稳定转换成统一 `symbol`；
- 重复同步保持幂等；
- 名称变化产生不重叠历史；
- 客户端身份只能查询 `api_v1.securities`，不能写 `core.security`；
- 任一记录可通过 `ingestion_id` 追溯到 Raw Manifest。
