# 服务接口与 Agent 接入评估 v1

> 状态：有效
> 日期：2026-07-29
> 依据：`adr/ADR-0010-PostgREST稳定查询与Agent工具契约.md`

## 1. 消费者用例与目标

以下是接口容量目标，不是生产环境实测值。生产部署后应从 PostgREST 日志按相同场景记录 P50/P95、错误率和返回行数；未达目标再以数据决定索引、缓存或服务层。

| 消费者 | 主要查询 | 单请求上限 | 目标 P95 | 目标并发 | 建议身份速率预算 |
| --- | --- | ---: | ---: | ---: | ---: |
| 研究脚本 | 单证券十年原始/复权日 K | 5000 行 | 2 秒 | 4 | 60 次/分钟 |
| 看板 | 单日全市场价格、收益率和市值 | 5000 行 | 1 秒 | 20 | 120 次/分钟 |
| 回测 | 多证券历史，客户端按证券/日期分页 | 5000 行/页 | 2 秒/页 | 4 | 60 次/分钟 |
| AI Agent | 证券搜索、短区间行情、分类成员 | 建议 500 行；硬上限 5000 | 1 秒 | 10 | 60 次/分钟 |

批量回测不得用一个无界响应读取全市场多年数据。如果分页仍不能满足吞吐，再用独立 ADR 评估 Parquet 导出/对象存储，而不是扩大在线 RPC 上限。

## 2. 能力评估

| 需求 | PostgREST View/RPC | 是否需要 FastAPI/MCP |
| --- | --- | --- |
| 证券搜索 | 有界 SQL RPC | 否 |
| 原始日 K | `api_v1.daily_bars` + 有界 RPC | 否 |
| 版本一致的复权日 K | RPC 先解析一个 CalculationRun | 否 |
| 单日行情/指标/市值编排 | 单个 SQL RPC | 否 |
| 任意日期分类成分 | 最新完整快照 RPC | 否 |
| Agent 工具调用 | JSON Schema 映射 PostgREST RPC | 否 |
| 跨 Raw/Parquet、流式导出 | 当前没有已确认用例 | 出现需求后评估 |

结论：当前 PostgREST 足够。FastAPI 和 MCP 均不建设。

## 3. RPC 契约

所有请求使用 `POST /rest/v1/rpc/{function}` 和 JSON 参数。稳定契约见：

- `contracts/postgrest-openapi-v1.json`
- `contracts/agent-tools-v1.json`

示例仅展示字段，不包含真实地址或凭据：

```http
POST /rest/v1/rpc/query_adjusted_daily_bars
Content-Type: application/json
apikey: <publishable-key>

{
  "p_symbol": "SSE:600000",
  "p_start_date": "2026-07-01",
  "p_end_date": "2026-07-29",
  "p_adjustment_type": "forward",
  "p_algorithm_version": "1.1.0",
  "p_limit": 1000
}
```

指定 `p_calculation_id` 可以复现历史结果；省略时选择覆盖整个请求范围的最新成功批次。响应中的 `calculation_id`、算法版本、输入哈希和计算时间必须作为研究/回测结果元数据保存。

## 4. 权限、边界和错误

- `anon`、`authenticated` 只能 SELECT `api_v1` View 和 EXECUTE 已发布 RPC；
- RPC 使用调用者权限，不使用 SECURITY DEFINER 绕过 RLS；
- 证券搜索上限 100，其他查询上限 5000；
- 日 K 日期范围上限 3661 天；
- statement timeout 为 5 秒；
- SQLSTATE `22023`：参数无效；
- SQLSTATE `P0002`：不存在请求的版本/快照；
- SQLSTATE `42501`：权限不足；
- SQLSTATE `57014`：超时。

PostgREST 将数据库错误映射为 HTTP 响应；消费者同时记录 HTTP 状态和 SQLSTATE/code，不依据可变的自然语言 message 编写逻辑。

## 5. 限流与可观测性

数据库强制单请求成本边界。每身份/IP 的请求频率由 Supabase 网关或前置反向代理实施，建议预算见第 1 节；具体生产配置、密钥和公网治理继续由 Issue #15 管理。

部署后至少观测：

- RPC 名称、HTTP 状态、数据库 SQLSTATE；
- P50/P95/P99 延迟和超时率；
- 响应行数/字节数；
- 每身份/IP 请求率（日志中不得输出 Token）；
- PostgreSQL 慢查询与索引命中情况。

## 6. 兼容策略

`api_v1` 允许向后兼容地新增可空返回字段、新 View/RPC 或带默认值参数。以下变化必须新建 RPC 名称或 `api_v2`：

- 删除、重命名字段；
- 改变单位、调整口径或字段含义；
- 改变默认算法版本导致同一请求产生不同语义；
- 把原先成功的有效输入改为失败。

Agent 工具 Schema 与 OpenAPI 必须在同一 PR 更新，并通过端点集合、严格输入、只读和敏感信息契约测试。

## 7. 验证

CI 在隔离 PostgreSQL 中验证：

- migrations 从空库执行且可重复跳过；
- RPC 返回闭区间、行数上限和标准证券代码；
- 复权/市场快照只使用一个 CalculationRun；
- Classification 查询按 as-of 选择完整快照；
- 无效输入返回 `22023`；
- `anon`、`authenticated` 可执行 RPC 但不能读取内部表；
- OpenAPI 和 Agent 工具端点一致，不包含内部 Schema 或 Secret。
