# Tushare 2000 积分接口清单

- 核对日期：2026-08-02
- 状态：外部权限快照；“当前项目状态”列单独记录本项目实现情况
- 官方依据：[基础积分权限表](https://tushare.pro/document/1?doc_id=108)、
  [积分与频次权限表](https://tushare.pro/document/1?doc_id=290)及各接口页面

## 结论

2000 积分可以访问官方基础积分权限表中最低门槛不高于 2000 的常规接口。
2000 分档通用额度为每分钟 200 次、每天每个 API 100,000 次；若接口自己的页面给出
更具体的频次、单次行数或总量限制，以接口页面和账户权限中心的实时结果为准。

分钟数据、盘中实时行情、港美股行情、新闻、公告等是独立权限，不能因为账户有
2000 积分就直接访问。特色数据通常需要 10000/15000 积分，亦不在本清单内。

### 当前账户只读实测

2026-08-02 使用本地 Worker Token 做了最小请求验证，不记录响应数据或 Token：

| API | 结果 | 返回行数 |
| --- | --- | ---: |
| `stock_basic` | 可访问 | 5534 |
| `trade_cal` | 可访问 | 3 |
| `daily` | 可访问 | 1 |
| `daily_basic` | 可访问，包含请求的 `free_share` 字段 | 1 |

其余接口依据官方权限文档记录，未逐个发起请求，以避免无意义消耗配额。
`stk_holdernumber` 的实现状态不表示本地账户已在该次实测中调用，也不表示已执行生产迁移或回填。

`daily_basic` 已确认包含以下股本字段，单位均为万股：

- `total_share`：总股本；
- `float_share`：流通股本；
- `free_share`：自由流通股本；
- `turnover_rate_f`：按自由流通股本计算的换手率；
- `total_mv`、`circ_mv`：总市值、流通市值，单位万元。

因此，2000 积分账户可以获取严格意义上的每日自由流通股本 `free_share`。它与通达信
`LTAG` 普通流通 A 股字段不同，不应混为同一指标。

## 2000 积分仍不可访问或不能推定可访问

| 接口/类别 | 原因 |
| --- | --- |
| `share_float` | 官方最低 3000；它表示限售股解禁，不是 `free_share` |
| `index_dailybasic` | 最低 4000 起 |
| `fund_portfolio`, `fund_adj`, `opt_daily` | 最低 5000 起 |
| 特色数据 | 通常至少 10000，15000 才无特色数据总量限制 |
| A 股/ETF/指数/期货/期权历史分钟与实时分钟 | 独立权限，不属于积分权限 |
| A 股、ETF、指数、申万指数实时日线 | 独立按月权限 |
| 港股、美股行情及财报 | 独立权限；`hk_basic` 除外 |
| 新闻、公告、研报、政策库 | 独立权限 |
| 盘前股本、集合竞价、互动问答 | 独立权限 |

## 接入建议

1. `daily_basic` 应保持为每日估值/股本快照领域，不得塞入 `ShareCapitalRecord`；
   `stk_holdernumber` 已按独立 ShareholderCount 点时事实边界实现。
2. `free_share`、`float_share`、`total_share` 从“万股”转换为“股”时乘以 10,000，
   使用 `Decimal` 校验后再转换为整数。
3. 周线、月线继续由分析项目从 Core 日线按交易日聚合；不要同时混用 Tushare
   `weekly/monthly` 作为同一事实来源。
4. 采集器应按接口分别限速，并记录积分不足、独立权限缺失和当日总量用尽三类错误；
   不应仅依赖统一的 200 次/分钟配置。
   ShareholderCount 默认按每分钟 180 次配置，为官方 200 次上限预留余量。
5. 本文是日期化快照。Tushare 会调整门槛、频次和独立权限价格，实施新接口前必须
   再检查具体接口页与账户权限中心。
