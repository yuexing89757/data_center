# ADR-0046：东方财富股票龙虎榜采集与只读契约

- 状态：Proposed
- 日期：2026-08-24
- 关联 Issue：#65
- 决策者：项目所有者（尚未接受）
- 影响：新增 `TradingBillboard` 领域、东方财富专用 Provider、Worker 日任务和三个只读契约

## 背景

消费者需要查询 A 股每日龙虎榜上榜证券、上榜原因以及买入/卖出前五席位。当前项目只有
Tushare 外部能力清单提到龙虎榜接口，没有对应领域模型、Provider 能力、标准事实、持久化或
公开读取契约。消费者若直接依赖东方财富网页字段，将绕过 Raw、校验、采集血缘和稳定 API。

龙虎榜不是普通日 K 的附属列：一只股票同日可能因多个原因产生多条披露，每条披露又分别拥有
买入和卖出席位。东方财富席位响应还会混入可转债，多条“机构专用”可能重复使用代码 `0`，
且前五席位对应侧金额之和不保证等于汇总金额。

## 提议决策

1. 新增独立 `TradingBillboard` 领域。聚合根 `TradingBillboardRecord` 表示一条上榜汇总，
   `TradingBillboardSeatRecord` 表示其买入或卖出席位。
2. 首期只接受 `SSE`、`SZSE`、`BSE` 股票。可转债行保留在 Raw，但不进入标准事实；未来扩展
   可转债必须独立决策其标识和公共契约。
3. 首个且唯一 Provider 为 `eastmoney`。新增专用 `TradingBillboardProvider` capability，
   不扩大普通 `MarketDataProvider`，不加入自动路由，也不在失败时切换来源。
4. Provider 每个交易日分页读取东方财富上榜汇总、买入席位和卖出席位三个数据集，并将三者视为
   一个原子来源批次。任何一个数据集不完整时，整个交易日不写标准事实。
5. 汇总自然键为 `(source_code, source_event_id)`，并以
   `(symbol, trade_date, reason_code)` 检测语义冲突。席位自然键为
   `(source_code, source_event_id, side, rank)`。
6. `TradingBillboardSeatRecord` 必须显式携带 `symbol` 和 `trade_date`，并与父汇总的来源事件、
   股票和交易日共同接受领域校验及数据库组合外键约束。
7. 来源代码 `0` 不视为可靠营业部身份，标准化为 `seat_code=None`；席位名称按披露原文保存。
   不对席位代码或名称建立唯一约束。
8. 东方财富没有独立席位名次字段。Normalizer 在每个事件、每个方向内按对应侧金额降序，并以
   规范化席位代码、名称和行内容哈希确定性处理同额记录。相同 Raw 重放必须产生相同名次。
9. 金额单位统一为 CNY，百分比使用百分点；所有价格、金额和比例由 JSON 数字文本直接构造
   `Decimal`，不得经过 `float`。缺失保持 `None`，不得擅自补零。
10. 每个成功交易日创建一个 IngestionRun 和一个不可变 Raw JSONL，schema 为
    `eastmoney.trading_billboard.v1`。Raw 行保留来源字段，并用 Pipeline 自有 `record_kind`
    区分汇总、买席位和卖席位以支持版本化重放。
11. 新增内部 `billboard.entry` 和 `billboard.seat`。同一来源事实重跑幂等；来源修订时在一个
    事务内更新汇总并替换其席位，最新事实指向新 ingestion，旧响应继续由 Raw 和采集事实保留。
12. 新增 Worker 代码任务 `trading-billboard-daily`，每个工作日 20:30 Asia/Shanghai 触发，
    执行前检查统一交易日历。日期范围回补逐交易日独立运行和提交。不得增加 OS 计划任务。
13. 新增三个 `SECURITY INVOKER`、5 秒超时的 `api_v1` RPC：按准确交易日查询、按股票与日期
    范围查询、按席位与日期范围查询。所有读取只访问数据库，不在请求时回源东方财富。
14. 席位查询要求精确提供 `seat_code` 或 `seat_name` 中的一个，可选 `buy`/`sell` 方向；不提供
    模糊名称搜索。日期范围最多 366 天，limit 为 1～500，offset 为 0～10,000。
15. FastAPI 只能调用上述有界 `api_v1` RPC。PostgREST、Agent Tools 与 FastAPI 三份契约必须
    同步更新，消费者不得直接访问内部 schema。
16. 游资身份映射、营业部排行、成功率、上榜后收益、东方财富文本解读和交易建议不进入数据中心。
17. 生产调度启用前，项目所有者必须完成东方财富条款、交易信息权利、长期保存和再分发范围审阅。
    未完成时只允许 mocked 测试和受控只读验证。

## 后果

- 消费者可以通过稳定契约查询可追溯的龙虎榜汇总与席位，不再依赖东方财富字段和内部表。
- 每个交易日需要三组有界分页请求、一个 Raw 对象和一个原子数据库事务；任一硬不变量失败会让
  当日批次失败，而不是发布部分结果。
- 来源没有项目可依赖的公开版本或 SLA，字段漂移、分页漂移和限流会直接表现为可诊断失败。
- `source_event_id` 和 `reason_code` 首期保留来源语义。若接入第二来源，必须先决定原因代码
  namespace 和跨来源事件对齐，不能静默合并。
- 当前事实表保留最新接受版本，来源修订的旧版本通过 immutable Raw 和 ingestion lineage 重放。

## 接受条件

本 ADR 只有在项目所有者明确将状态改为 `Accepted` 后才可作为编码依据。接受前应确认：

- Issue #65 的范围、非目标和验收标准保持一致；
- `TradingBillboard` 领域详设中的字段、自然键、失败语义和三个读取契约已审阅；
- 东方财富生产采集与再分发权利审阅责任人和启用门禁已明确；
- 实施必须包含 ordered migration、Provider/Domain/Service 测试、隔离 PostgreSQL 集成测试、
  Worker/Operations 测试和三份公开契约同步。
