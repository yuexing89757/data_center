# ADR-0016：跨平台调度与运行可靠性

- 状态：Accepted
- 日期：2026-08-02
- 关联 Issue：#30
- 决策者：项目所有者
- 影响：生产调度、运行恢复、健康检查、部署与集成测试

> Worker 产品入口和健康检查命令已由 ADR-0017 取代；本 ADR 的单进程任务模型、完整性
> 门禁、锁、恢复和持久化决定继续有效。

## 背景

普通日采集曾由 Windows Task Scheduler 启动，而股票每日指标由 APScheduler 启动。
双重调度增加了重复运行、部署漂移和 Linux 迁移风险。完整市场快照、Core 保留和进程
异常退出也需要明确的安全边界。

## 决策

1. 单个独立 APScheduler 进程承载所有生产计划：工作日 20:00 执行 `daily-run`，20:30
   执行股票每日指标，每小时执行陈旧采集恢复。操作系统或容器只负责进程监管。
2. Scheduler 使用单线程执行器、固定任务 ID、SQLite 持久 JobStore 和进程生命周期内的
   PostgreSQL advisory lock；不再维护 Windows Task Scheduler 定义。
3. 收到 SIGINT 或 SIGTERM 后停止接收调度并等待在途任务结束。启动时以及每小时把超过
   60 分钟仍为 `running` 的批次标记为失败。
4. 每日指标全市场快照为空、达到 Provider 单次响应上限或低于上一有效快照的 90% 时，
   阻断 Core 写入。Raw 和质量审计仍保留，以便诊断与重放。
5. 只有日历同步成功，且快照为 `succeeded`/`partial`、接受行数大于零后，才允许执行
   一个月 Core 保留清理；失败或休市不得触发删除。
6. `market-data-center-scheduler --check` 是只读健康接口，核验固定任务、陈旧运行和最近
   非空快照。Linux systemd 使用持久 StateDirectory，并限制可写路径。
7. PostgreSQL 集成测试只允许连接隔离测试实例。仓库提供临时 PostgreSQL Compose 环境，
   不得复用生产数据库。
8. 本条关于 Linux 本地 `vipdoc` 的要求已被 ADR-0024 取代；Raw 与 JobStore
   通过持久卷或 `/var/lib/market-data-center` 保存。外部行情文件更新不属于本进程职责。

## 后果

- Windows 与 Linux 使用同一业务调度实现，计划定义不再随宿主系统分叉；
- SQLite JobStore 与 Raw 当前仍是单机文件系统资源，多副本高可用需要新的 ADR；
- advisory lock 防止多实例主动运行，但部署仍应配置单副本；
- 十天健康阈值容纳长假，仅用于运维告警，不替代交易日历判断。

## 验收

- 单测覆盖三类任务、快照完整性、保留前置条件和健康判定；
- Ruff、mypy 和非隔离测试全部通过；
- PostgreSQL 集成测试可由 Compose 脚本重复启动并在结束后清理；
- systemd 单元支持 SIGTERM 优雅退出和持久状态目录。
