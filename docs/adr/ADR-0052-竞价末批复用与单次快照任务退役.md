# ADR-0052：竞价末批复用与单次快照任务退役

- 状态：Accepted
- 日期：2026-09-04
- 关联 Issue：#73
- 决策者：项目所有者
- 修订：ADR-0027、ADR-0032、ADR-0034

## 背景

Worker 当前在工作日 09:15:00 至 09:25:20 每 20 秒采集一次沪深上市股票全集，随后又在
09:25:30 执行一次相同范围的全市场竞价快照采集。后一个任务与序列最后两轮的异步 Writer
并发，重复访问行情 Provider 和 PostgreSQL。2026-09-04 的生产事实显示，09:25:30 单次快照
执行约 49 秒，同时序列末两批写入出现明显排队。

两个公共接口目前依赖 `realtime.call_auction_market_snapshot`：批量竞价快照查询直接返回该表
来源事实，一字涨跌停接口在其上执行确定性主板规则。序列表
`realtime.call_auction_market_series_snapshot` 已包含 09:25:20 末批所需的价格、量额和买卖五档，
可以成为两项读取契约的唯一来源。

## 决策

1. `api_v1.query_call_auction_market_snapshots(date,text[])` 固定选择
   `realtime.call_auction_market_series_snapshot` 的 `batch_code='092520'` 数据。
2. 精确日期只在该日期内选择。所选末轮 succeeded attempt 优先；没有 succeeded 时允许该末轮
   selected partial attempt；末轮没有可用 attempt 时返回 not found。不得回退到更早轮次、其他
   会话或其他日期，也不得拼接多个 attempt。
3. `api_v1.query_auction_one_price_limits(date)` 使用相同末批来源。显式日期不回退；省略日期时
   选择最近存在可用 09:25:20 末批的交易日。既有沪深主板范围、上市阶段、百分之十涨跌停、
   一字价格形态和遗漏计数规则不变。
4. 序列表不新增 `seal_amount` 列。两个 RPC 在读取时执行同一确定性表达式：仅当卖一、卖二、
   卖三数量分别为空或零，且买一价格、买一数量完整时，返回 `bid1_price * bid1_volume`；否则
   返回 `NULL`。
5. FastAPI 路径、请求参数、响应字段、数值和时间序列化保持兼容。响应中的 ingestion lineage
   改为序列末轮所选 attempt 的 ingestion ID 和状态。
6. 从受控调度目录移除 `call-auction-market-snapshot-daily`，Worker 不再在 09:25:30 发起重复的
   全市场采集。任务页和调度测试同步反映该 job 已退役。
7. 保留 `realtime.call_auction_market_snapshot`、历史数据、既有迁移和非调度采集实现。本变更不
   删除或改写历史事实，也不复制序列末批到旧表。
8. 接口仅在 09:25:20 末轮完成采集并由单 Writer 提交后可用；尚未落库时返回 not found，不能
   用 09:25:00 等更早轮次制造临时结果。

## 后果

- 每个交易日减少一次约 5,215 只证券的行情读取、Raw 写入和数据库批量写入；
- 消除 09:25:30 单次快照与竞价序列末批 Writer 的已知资源竞争；
- 公共接口代表的观察时点由独立 09:25:30 任务改为固定 09:25:20 序列末批；
- 旧表成为只保留历史事实的内部表，不再由代码目录中的定时任务新增数据；
- 末批失败或延迟时保持显式不可用，不牺牲时点和单批一致性。

## 验收

- ordered migration 原位替换两个 `api_v1` RPC，签名和授权不变；
- PostgreSQL 集成测试覆盖 succeeded 优先、partial 兜底、末批缺失、禁止较早轮次和日期回退、
  seal amount 以及一字涨跌停结果；
- 调度目录、Scheduler 测试、生产检查、运行手册和三个已签入 API 契约同步；
- 本地 Ruff、mypy、pytest 和隔离 PostgreSQL integration gate 通过后方可发布。
