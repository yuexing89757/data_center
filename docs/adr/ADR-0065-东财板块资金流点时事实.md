# ADR-0065：东财板块每日资金流点时事实与采集

- 状态：Accepted
- 日期：2026-10-06
- 决策者：项目所有者
- 影响：BoardMoneyflow、Tushare Provider、Raw 重放、Worker 调度、CLI
- 前置：ADR-0047（股东人数点时事实）、ADR-0064（十大流通股东点时事实）

## 背景

东方财富按交易日发布概念、行业与地域板块的资金流向统计：当日涨跌幅、收盘点位、主力
净流入额与净流入率、超大单/大单/中单/小单净流入及占比、小单净流入最大成分股与当日
排名。它是板块级热度与资金迁徙的客观来源事实，不是证券级行情，也不是主观板块标签。

Tushare `moneyflow_ind_dc` 接口（经 `TUSHARE_ENDPOINT` 兼容端点）按交易日返回全部
板块：实测单日约 1031 行（概念约 500+、行业 80+、地域 30+，含少量其他来源类型），
远低于单次 6000 行上限，单日全市场一次请求即可完整读取。

## 决策

1. 新增 provider-neutral `BoardMoneyflow` 领域，保存标准板块标识 `board_code`
   （`DC:BK0145` 风格，来源 `BK0145.DC` 在 adapter 边界标准化）、`trade_date`、
   `board_type`（concept/industry/region 枚举，来源中文值在边界映射）、板块名称快照
   `name`、`pct_change`、`close`、主力 `net_amount`/`net_amount_rate`、超大单/大单/
   中单/小单净流入额与净流入率（可空 Decimal）、`top_small_buy_stock`（可空）与
   `rank`（可空正整数）、`source_code`。首期来源仅为 `tushare`，Raw schema 固定为
   `tushare.board_moneyflow.v1`。
2. Core 表为 `core.board_moneyflow`。主键是 `(trade_date, board_code)`，追加而不
   覆盖：重复自然键 `on conflict do nothing`，保留既有行的首次血缘与
   `first_observed_at`。板块名称作为公告日快照随行保存，不建立板块主数据或名称变更
   历史。
3. 金额语义为主力/单类净流入额（元，可负），净流入率与涨跌幅为百分比数值（可负）。
   `pct_change` 与 `net_amount` 是核心事实：来源为空的行表示该板块当日无可发布资金
   流事实，完整保留在 Raw，不生成 Core 记录，不使批次失败。`close`、各单类金额/
   比率、`rank`、`top_small_buy_stock` 允许缺失（标准化为 `None`，零与缺失语义不同）。
4. 来源 `content_type` 只有 概念/行业/region 三类被接受，其他来源类型在 adapter 边界
   硬失败（显式暴露新类型而不是静默丢弃）。行内 `trade_date` 与请求交易日不一致、
   非 `BK*.DC` 板块代码、批内 `(trade_date, board_code)` 重复均为硬错误；重复冲突对
   整体隔离为质量拒绝，不静默择一。
5. 每个实际请求产生一个 IngestionRun、一个不可变 Raw 对象和一个 manifest；一次同步
   窗口的全部请求完成后在一个数据库事务中发布，任一请求失败时中止并标记全部已准备
   批次 `failed`，不发布部分事实。请求节奏复用 ADR-0047 的 Tushare 股东接口限速器。
6. 每日增量在 Worker 内工作日 17:00 Asia/Shanghai 运行，重扫当日及此前 4 个自然日
   （共 5 日），使来源的盘后修正可见。`BOARD_MONEYFLOW_DAILY_ENABLED` 默认关闭，
   部署后显式启用。手动补采走 `market-data-center board-moneyflow` CLI（Workflow
   `board_moneyflow_daily`，`TriggerSource.MANUAL`），显式日期区间，非交易日为合法
   空响应。历史回补由显式 CLI 区间完成，不注册额外定时任务。
7. 首期不新增 `api_v1` 公开视图或 RPC；公开只读契约待消费方分析需求明确后按宪法流程
   另行决策。在此之前任何消费者不得依赖 `core.board_moneyflow` 作为稳定契约。
8. 所有定时触发只进入 `market-data-center worker` 的 APScheduler 任务目录。不得增加
   Windows Task Scheduler、cron 或其他操作系统级采集触发器。

## 后果

- 数据中心获得按 `(交易日, 板块)` 粒度追加的板块资金流事实，单日约千行，无截断拆分
  需求；接口若未来触及行数上限，按 ADR-0064 的显式失败语义处理，不静默截断。
- 板块名称与成分不追溯变更：名称随行快照保存，板块改名后按新名称追加，历史行保留
  旧名称；板块成分股不在本决策范围。
- 5 日滚动窗口不能发现更早的来源修正；更长历史的重写以显式 CLI 区间执行。
- 首期不抽象个股级资金流（`moneyflow_dc`）、板块成分（`dc_index`）或同花顺板块资金
  流，也不引入第二来源。

## 验收

- Domain 校验/分区、Tushare adapter（字段映射、类型映射、空值跳过、Raw 重放）、
  Service（窗口、中止语义）、批量持久化（单事务、自然键预检、abort 不发布事实）
  均有聚焦测试。
- PostgreSQL 集成测试覆盖 migration、约束（板块代码格式、类型枚举、非空名称、正
  名次）、追加幂等（重复批次不重复不覆盖）、Worker 最小授权与 RLS 清单。
- 不改变 `contracts/postgrest-openapi-v1.json`、`contracts/agent-tools-v1.json`、
  `contracts/fastapi-openapi-v1.json`。
- Ruff format/check、mypy、pytest 和隔离 PostgreSQL integration gate 通过；无法运行的
  检查必须报告准确命令和原因。
