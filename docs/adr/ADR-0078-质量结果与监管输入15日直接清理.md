# ADR-0078：质量结果与监管输入15日直接清理

状态：Accepted，2026-11-10 项目所有者明确要求。

本决策覆盖 ADR-0058 对 `audit.quality_result` 的30日白名单归档前置要求，
不改变其他表、Raw、既有归档文件或备份的策略。

1. 既有 Worker `data-cleanup-daily` 继续每天上海时间03:00执行。
   `audit.quality_result` 按 `created_at`，`regulation.monitor_input` 按所属
   `regulation.calculation_run.trade_date` 保留15个自然日。
   截止为执行日上海零点向前15日，严格早于截止的记录直接删除，截止当天保留。
2. 质量结果覆盖所有数据集、规则、严重级别与汇总，不再创建归档、汇总或归档回执。
   旧归档及回执保留；15日前在线质量证据不再保证可查或恢复。
3. 只删除监管输入，不连带删除监管事件、批次、上下文、规则结果或预警。
   解除事件对输入的永久外键依赖，保留事件对上下文和证券的外键，
   用发布时触发器保证新事件存在输入。正在运行的监管批次不清理。
4. 首批删除同一批次输入的事务先设置 `monitor_context.inputs_expired_at`；
   输入读取和检查点加载明确失败，不能把部分清理或空输入当成正常空名单。
   新输入不得追加到已过期批次。历史重算需要的前序检查点过期时明确拒绝。
5. 两张表交替分批处理，每批最多5000行，各批独立提交，共用现有维护锁、
   03:00维护窗口与时间预算。达到预算、锁冲突或仍有过期行时记录partial及已提交数量。
   直接删除不受归档空间门槛约束；磁盘信息仍写入执行报告。
6. Worker DELETE/UPDATE权限由RLS限定到已过期目标；仅授予上下文过期标记列UPDATE。
   `20261110000100_direct_quality_monitor_retention.sql` 只调整索引、约束和策略，
   不删除历史记录，生产仍须通过受保护迁移流程应用后再更新Worker。
7. 默认CLI只读预览，显示有上限的候选数量。执行报告记录两表删除数量、15日策略和无需归档。
   删除只保证数据库内部空间可复用，不包含VACUUM FULL、REINDEX或磁盘物理收缩。

实施与上线状态必须分别核验，不能把本文件或本地测试当作生产清理已经发生。
