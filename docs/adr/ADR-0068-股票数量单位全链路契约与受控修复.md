# ADR-0068：股票数量单位全链路契约与受控修复

- 状态：Accepted（项目所有者于 2026-10-23 在本聊天明确接受设计并授权本地实现）。
- 日期：2026-10-23。
- GitHub Issue：[#92](https://github.com/yuexing89757/data_center/issues/92)；实施计划及进度以此为准。
- 设计与只读证据：[成交量单位排查与整改设计](../superpowers/specs/2026-10-23-stock-quantity-units-design.md)。
- 关联：ADR-0006、0010、0011、0012、0023、0024、0040、0054、0058、0066、0067，及 Issue #90。

## 背景

现有契约要求股票数量为股，但远程 TDX v1 回放保留未换算手数，AKShare 日 K 存在同类入口缺漏。
当前行血缘识别出 224,175 条远程 v1 股票日 K 候选，另有 20 条无可用 Raw manifest；
涨停快照也保存了这些日 K 的数量输入。新采集修好不足以阻止旧回放、快照和其他入口重新发布错误值。
数量字段还涉及盘口、竞价指示、JSON 技术因子和独立指数/可转债业务，不能统一盲乘100。

## 接受的决策

1. 标准股票成交、逐笔、竞价、各档及累计数量事实统一整数股；均量等统计量用 Decimal 股。
   金额用 Decimal 元。零与缺失分离；不引入逐笔/tick采集或新MCP服务。
2. 仅 Provider 处理来源单位。按 Provider、endpoint、采集schema、品种、字段登记可验证证据，
   未确认/矛盾单位硬失败。不得依量级、价格或日期猜测，也不在 Calculator、SQL/API 里补乘100。
3. 不可变 Raw 保留其原版本和来源单位。标准化另记单位契约/normalizer版本与新 ingestion血缘。
   替代 Issue #90 及 RemoteTdxDailyBar 增补中“旧远程v1保留错误标准结果”的要求：
   旧版可以被正确认证转换或明确拒绝，不能再次作为股输出未换算手数。
4. 标准归档结构不再按线上的手转换。指数、THS、可转债张、基金份及数量敏感技术因子采用独立契约，
   不沿用股票×100。任何因子缩放变化必须升目录/算法版本。
5. 增加按 ingestion/字段组的持久单位认证及受限、版本化历史修复账本，通过有序 SQL migration 演进，保持 RLS、最小权限与有界查询。
   修复默认只读预览，按 Raw 证明的目标值分批 compare-and-set，保留前后血缘、恢复依据、冲突和断点。
   禁止整库乘100、修改Raw、重复换算或覆盖并发新事实。
6. 未认证历史数量在标准读与计算边界明确隔离/缺失，保留事实主体和质量原因。
   普通事实返回数量null及quantity_quality；显式请求有问题的旧不可变版本返回409。
   新采集/回放单位不明则整批标准写入失败，不用null代替未知来源值后继续标成功。
   不可变快照按既有版本机制重建、替代，不原地篡改或静默回退日期。
7. 同步领域详设、数据库/API字段注释、OpenAPI/Agent契约及调用方去补偿清单。
   明示“100股就是100股，不是100手”。既有文档承诺股的数值纠错不得被伪装为无数值影响的兼容变更。
8. 代码/脚本编写及隔离测试与生产操作分离。生产migration、历史修复、回放重算、服务切换仍按现有授权和运行手册执行。
   未完成历史修复、Raw/缓存恢复与多入口端到端验证前，不得宣布全面统一。

## 后果与验收

需要覆盖现有多个 Provider、Raw 版本、快照与接口；未知来源证据可能导致数量暂不可发布。
这项成本优先于继续提供看似有值但单位不明的数据。全部候选、已修复、无法修复、调用方未适配和未执行操作必须可查。

完整字段/来源范围、修复事务、回滚限制、兼容处理、测试矩阵和分阶段验收见关联设计。
设计接受当时仅授权本地实现。2026-10-23 后续明确要求部署线上环境，已执行代码、
四个迁移和 Worker/API 切换，见[生产记录](../runbooks/quantity-units-production-2026-10-23.md)。
所有者随后明确授权历史修复与重算最近一个月，执行范围固定为2026-09-23至2026-10-23（含首尾），
见[月度修复记录](../runbooks/quantity-units-monthly-2026-10-23.md)。
该范围不等于来源不明数据可猜测认证，也不等于旧快照可原地修改；具体能力与剩余缺口以实际证据为准。

2026-10-23竞价准入澄清：序列Raw v1是股的标准归档，v2是保留原生
`pytdx_hq.security_quotes.v1`手数量的包络。已存正确事实可经完整原会话/轮次/尝试/
冻结证券集/Raw投影证明后原血缘认证；认证本身不重新标准化写入或改写事实。
该维护路径与禁用的通用竞价Raw回放分离，细节及实际执行状态见
[当日竞价恢复记录](../runbooks/auction-quantity-recovery-2026-10-23.md)。


## 2026-10-24 技术因子来源尺度修正（Accepted）

项目所有者最终明确同意：OBV、EMV、MAEMV 按 Tushare 原生指标值完整保存和返回，
分别保持不复权、前复权、后复权口径，不做手/股换算。本决定替代此前该领域的新批次
整批阻断及叶子null隔离方案。三个指标采用独立的来源指标契约，不声明为股或无量纲，
不将来源原生尺度误写为已认证的股票数量单位。其他股票数量、金额门禁不变。

所有因子继续执行日期、证券、完整目录、有限数值、重复键及市场覆盖校验；
合法零和负数保留，来源缺失为null，Raw不可变。公开目录升级stock-technical-factor.v3，
来源目录保持v1，quantity_quality.status=source_native、reason=provider_native_factor_scale。
v2曾返回null的9个叶子现在返回来源原值，调用方不得额外乘除100；适用于所有查询日期。
不重新解释或改写历史源JSON。通过20261024000100迁移更新既有只读投影视图，
不更改表结构、RPC边界或权限；FastAPI/PostgREST/agent契约同步。
标准请求日期统一ISO；历史YYYYMMDD在重放的新批次中规范化，原审计不改写。
继续使用既有Worker晚间三次及次晨补偿，无新增OS任务。

## 2026-10-24 监管股票指数既有契约恢复

用户要求解决监管基准`index_daily.vol`实际阻断。ADR-0048的2026-10-01与10-06澄清
已批准四个监管股票指数、独立`tushare.index_daily.v1`及手转聚合股数/千元转元。
[官方doc95](https://tushare.pro/document/2?doc_id=95)独立给出来源单位。
因此将该精确endpoint/schema的`index`身份登记为来源手、标准聚合股数，1手=100股；
金额独立登记千元→元。指数点位不变，不能把指数视为可交易股票或机械推广到其他指数。
适配器仍校验四个来源代码白名单、日期、重复、缺值和整数股；
入库两组认证及显式来源元数据必须使用指数身份，采集与旧Raw重放共用相同转换。
无新领域、公式或数据库结构变更；不认证旧BaoStock指数或THS来源。
历史范围和实际部署状态见[恢复记录](../runbooks/regulation-index-units-2026-10-24.md)。
