# ADR-0074：竞价快照在线与历史统一有界读取

- 状态：Accepted（所有者先接受本地方案，随后于本聊天明确要求“修复生产数据”，授权本方案的生产修复及验收）。
- 日期：2026-10-24。
- 背景：所有者检查2026-10-19、2026-10-20竞价后，明确要求支持历史快照接口查询。
- 关联：ADR-0034、0050、0052、0054、0068；GitHub Issue #97。
- 修订范围：ADR-0054第10项对公共历史读取的限制，仅涉及以下两项查询。

## 决策方案

1. 扩展现有`query_call_auction_market_snapshots(date,text[])`及
   `query_call_auction_market_series_snapshots(date,text[],text)`，保持FastAPI路径、参数和响应结构。
   消费者按精确交易日查询当前仍保留的历史快照；不承诺超过实际历史保留窗口的数据。
2. 保留既有成功优先、所选partial兜底、精确Session/Round/selected ingestion选择。
   末批查询仅取`sample_seq=31 / 092520`；序列最多32轮，可按batch_code筛选。
   不回退其他日期、会话、轮次或attempt；没有事实继续显式缺失。
3. 在内部audit schema增加只读统一来源视图：对同一日期、Session、轮次和ingestion，
   只要在线表尚有事实，整批只读在线；在线完全不存在时整批读取历史。
   两份重叠不会重复返回，也不逐证券拼补不同物理副本或不同attempt。
   整批存在性探测不得带请求代码过滤；候选选择、items和missing_codes统一使用新来源。
4. 两个来源均沿用ADR-0068的持久认证、`audit.quantity_quality`及相同字段屏蔽规则。
   内部`audit.read_auction_snapshot_attempt`先限定日期/轮次/ingestion/请求证券，
   同次调用只计算一次原有质量门禁再投影各数量字段，避免逐字段/逐证券重复计算；不更改认证判定。
   未认证量额仍为null并附质量原因；
   不修改原始快照、Raw、单位数值、保留规则，不将历史批量复制回在线表。
5. 查询边界保持单日、1～500个六位代码、最多32轮、5秒statement timeout。
   精确trade_date条件下推到两个月度分区来源，复用日期/证券/轮次索引及轮次引用索引；
   隔离数据库测试和生产只读EXPLAIN/实际有界查询验证索引与耗时，必要时先补有序索引迁移。
6. 新视图不授予anon/authenticated/market_data_api直接SELECT；内部attempt reader也不授予这些角色
   EXECUTE。消费者只获原api_v1函数执行权限。
   FastAPI仍只调用api_v1 RPC，不直接读内部schema，不采集、不写库。
7. 不扩展一字涨跌停、形态、抢筹线等其他查询的历史语义。同步三份checked-in contracts、
   领域设计及运行手册，明确此次仅扩展两个快照接口。

## 实施与验收

- 先登记GitHub Issue，方案Accepted后编写失败集成测试，再新增有序SQL迁移。
- 覆盖history-only、hot-only、热历史重叠去重、同轮不同attempt隔离、partial、缺日期/轮次、
  batch_code、未认证量额null、认证后恢复、参数上限、权限与查询计划。
- 特别覆盖在线只剩一个证券而历史完整时不得按证券拼补；较新会话无事实时遵守两个RPC各自
  既有候选选择规则；500代码×32轮分别验证认证/未认证路径和单日分区裁剪。
- 完整本地门禁与隔离PostgreSQL验证通过后，经受保护production workflow应用迁移。
  服务文档更新按既有安全发布流程，不中断正在运行的采集，不作数据库备份。
- 19、20日各32个5224行批次逐Raw全字段核验，封存精确计划后逐批认证。
  认证只写证书与受限审计；HTTP/RPC返回值与历史事实逐项比较，保留真实来源null/zero。
- 生产修复已获本聊天后续明确授权；仍须完成本地门禁、受保护迁移及真实接口验收后才能声明上线。
