# ADR-0034：沪深全市场开盘竞价序列快照

- 状态：Accepted
- 日期：2026-08-14
- 关联 Issue：#48
- 决策者：项目所有者
- 扩展：ADR-0012、ADR-0017、ADR-0022、ADR-0026、ADR-0027、ADR-0028

## 背景

现有 `call-auction-market-snapshot-daily` 只在 09:26 保存一次沪深全市场来源事实，不能描述 09:15–09:25 集合竞价阶段随时间变化的来源状态。涨停池五档任务只覆盖前一交易日涨停池，不能替代沪深上市股票全集。

项目所有者要求工作日 09:15:00 至 09:25:20 每 20 秒保存一次沪深全市场开盘竞价快照，并要求与 09:26 表分开存储。当前全市场一次采集约 2.4 秒；每批 80 只能够落在 20 秒预算内。逐只请求不能满足该预算。

## 决策

1. 新增工作日 09:15 的 Worker job `call-auction-market-series`，内部生成 32 个采样点，最后计划点为 09:25:20。不得注册32个 APScheduler job，也不得使用 OS 调度。
2. 新增独立默认启用开关 `CALL_AUCTION_MARKET_SERIES_ENABLED`。开始时间、结束时间、20秒 cadence 和请求批量固定在代码目录，不进入环境配置。
3. 会话启动时冻结一次 `SSE/SZSE + stock + listed` 标准 symbol 全集并持久化完整 symbols、数量和内容哈希。BSE、ETF、可转债和指数不进入集合。
4. 每轮按最多80只顺序调用 PYTDX。一个 IngestionRun 只使用一个 endpoint；首 endpoint 不完整时可在轮次 deadline 前用第二 endpoint 从全集第一只重试。不得合并 partial attempts。
5. 新增 `realtime.call_auction_market_series_session`、`realtime.call_auction_market_series_round` 和月度分区 `realtime.call_auction_market_series_snapshot`。Snapshot 字段与09:26来源表一致，并增加 session、sample sequence 和 scheduled time。
6. 每轮硬截止为下一计划点，最后一轮硬截止为09:25:40。错过轮次显式失败，不补采、不伪造时间。只有精确覆盖冻结全集且全部硬校验通过的单 endpoint attempt 才能使 round succeeded。
7. 新增命名 APScheduler executor `morning_auction`，最大2线程，仅承载现有涨停池五档任务和新全市场序列任务。默认 executor 继续最大1线程；两项早盘任务各自 `max_instances=1`。
8. 新数据集与现有 `realtime.call_auction_market_snapshot`、09:26 job、开关、RPC和一字板契约完全隔离。首版不新增公共读取契约。
9. PostgreSQL按月分区并在线保留最近12个月；Raw JSONL、Manifest、IngestionRun和质量结果长期保留。创建/删除分区只能通过 ordered migration 和受保护发布流程，Worker不得执行DDL。
10. 首版 Raw replay fail closed。启用 replay 需要后续 Accepted ADR 明确 session、round、attempt和Raw envelope的一一关系。

## 后果

- 每交易日约新增16.7万行、每年约4,166万行来源事实，必须采用月度分区和有界索引；
- Worker早盘允许两个明确任务并行，但不会扩大其他任务的并发；
- 新任务可独立启停，不影响09:26快照；
- 节点超时、缺失和错过轮次保持可见，不用跨来源拼接制造成功；
- 新增 migration、领域模型、Persistence、Service、Scheduler、生产检查、运行手册和隔离PostgreSQL测试。

## 验收

- 32轮时槽、冻结全集、80只分批、deadline、endpoint failover和恢复规则有单元测试；
- migration集成测试覆盖分区、约束、RLS、grants、append-only和lineage；
- 调度测试证明两个早盘任务使用2线程专用executor，其他任务仍使用单线程；
- 生产发布不手工补采，下一交易日live gate验证32轮、09:26隔离和实际容量；
- Ruff、mypy、全量pytest、隔离PostgreSQL integration tests和发布检查通过。
