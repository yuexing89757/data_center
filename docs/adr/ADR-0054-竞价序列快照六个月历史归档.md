# ADR-0054：竞价序列快照六个月历史归档

- 状态：Accepted
- 日期：2026-09-13
- 关联 Issue：#78
- 决策者：项目所有者
- 扩展：ADR-0017、ADR-0034、ADR-0050、ADR-0051

## 背景

`realtime.call_auction_market_series_snapshot` 每个交易日约产生16.7万条、32轮沪深全市场竞价
来源事实。ADR-0050为保持早盘在线写入稳定，将该表缩短为最近三个已完成交易日，但后续回测仍需要
可直接查询的标准历史事实。不可变Raw长期保留并可用于审计与重放，却不适合作为首阶段的交互式回测
输入。

生产只读测量显示单日约16.7万行、平均行宽约223字节。历史表如果只追加并只保留必要索引，六个月
预计约两千万行、6～10 GB，符合当前阶段容量边界。

## 决策

1. 在`realtime` schema新增月度分区表
   `call_auction_market_series_snapshot_history`。它一比一保存在线Snapshot的全部事实字段、自然键、
   Session、Round和Ingestion lineage，包括32轮、五档、价量额和显式值语义。
2. 历史表同时保存succeeded与partial会话中已经持久化的合法事实。缺失事实保持缺失，不补造、
   不跨Session或Provider合并；回测消费者可以据Session/Round状态排除不完整日期。
3. 新增Worker job `call-auction-market-series-archive-daily`，每天上海时间02:30执行。任务归档在线表中
   所有严格早于当前上海日期且尚未归档的行，不只处理一个日期，以便从临时失败中自动追赶。
4. 归档使用`INSERT ... SELECT ... ON CONFLICT DO NOTHING`，按在线自然键幂等写入。历史表不允许
   UPDATE；Worker只有归档INSERT、校验SELECT和保留期DELETE所需的最小权限。
5. ADR-0050的03:00数据清理在删除在线旧行前，必须逐自然键证明目标行已存在于历史表。任一行未归档
   时fail closed，在线DELETE不执行。只比较总行数不构成完整性证明。
6. 历史表滚动保留六个自然月。03:00任务在在线安全清理后，删除
   `trade_date < reference_date - 6 calendar months`的历史行。月末按目标月份最后一天截断，保证
   截止日期确定且跨平台一致。历史删除失败只导致多保留数据，不回滚已经安全完成的在线清理。
7. 历史父表按`trade_date`月度分区，只建立`(trade_date, symbol, sample_seq)`回测定位索引以及主键
   所需索引，不复制在线采集专用的ingestion查询索引。分区只能由ordered migration创建和延伸；
   Worker不执行DDL、分区detach/drop或VACUUM。
8. 新归档workflow、现有清理workflow和步骤统计分别记录归档、完整性校验、在线删除和历史删除行数。
   归档失败由次日同一任务自动重试，03:00保护门禁继续阻止未归档数据丢失。
9. Raw、Manifest、IngestionRun、质量结果、Session、Round和Operations继续按既有策略长期保留。
   六个月只约束标准历史Snapshot，不授权删除这些审计事实。
10. 本决策不新增公共RPC、FastAPI路由或回测算法。消费者不得直接依赖内部历史表；公共历史读取必须
    在真实回测查询条件明确后另行设计有界契约和索引。

## 后果

- 在线表继续只承担最近三个已完成交易日的低延迟写入与现有API；历史表承担六个月标准事实保留，
  两者职责和索引独立。
- 部署后的首次02:30只能归档在线表仍存在的数据，不能从Raw自动恢复ADR-0050已删除的旧日期。
- 每日历史增长约16.7万行；发布和运行观察记录归档耗时、行数、分区容量及autovacuum。
- 历史DML删除保证逻辑保留期，但操作系统空间回收取决于PostgreSQL vacuum；受保护运维可以在后续
  migration窗口处理已完全过期的月分区。

## 验收

- 纯逻辑测试覆盖六个自然月截止、月末、闰年、周末与节假日重复运行；
- Persistence测试覆盖全字段复制、32轮、partial、幂等、逐键完整性门禁及事务边界；
- 隔离PostgreSQL测试覆盖分区、主键、外键、RLS、最小权限、禁止UPDATE和历史保留；
- Scheduler/Operations测试证明02:30归档和03:00清理顺序、固定代码目录时间及精确统计；
- 公共API与checked-in contracts不变；
- Ruff、mypy、全量pytest、隔离integration和生产发布检查通过。
