# ADR-0048：沪深主板与创业板监管异动规则测算

- 状态：Proposed
- 日期：2026-09-02
- 关联 Issue：#69
- 决策者：项目所有者
- 影响：新增 `Regulation` 领域、官方监管事件 Provider、基准指数日线采集、版本化规则计算、Worker 工作流及只读契约

## 背景

消费者需要在每日收盘后回答一个客观问题：某只沪深股票在下一交易日达到什么收盘涨跌幅时，
可能满足交易所现行的异常波动或严重异常波动条件。该问题不是价格预测，也不能把满足规则条件
解释为必然停牌、重点监控或其他监管措施。

当前系统已有 Security、Trading Calendar、未复权 Daily Bar、Capital、每日指标、版本化派生、
Worker 调度和只读 API，但没有监管规则、交易所正式事件、逐规则结果或 T+1 条件反解。若把
100%、-50%、200%、-70% 等阈值散落在 Python 分支中，规则修订无法通过数据版本和有效日期
审计；若仅从日 K 推断正式事件，又会混淆“本系统计算达到条件”与“交易所实际公布”。

上交所上证发〔2026〕41号和深交所深证上〔2026〕551号均明确《交易规则（2026年修订）》自
2026年7月6日起施行，2023年版本同时废止。首版因此只处理2026年7月6日及之后的沪市主板、
深市主板和创业板普通股票。

## 决策

1. 新增独立 `Regulation` bounded context。它保存官方规则配置、可追溯的交易所正式事件、
   版本化计算批次、每日状态、逐规则结果和面向消费者的客观预警。它依赖 Security、Trading、
   Market、Capital 和 StockDailyIndicator，不反向修改这些领域。
2. 内部 schema 为 `regulation`，包含 `rule`、`event`、`calculation_run`、`status`、
   `rule_result` 和 `warning` 六张表。消费者只通过 `api_v1` 读取，不获得内部表权限。
3. 规则唯一来源是沪深交易所现行有效官方文件。规则通过 ordered migration 装载；交易所、板块、
   规则类型、方向、窗口、阈值、次数、重置级别、基准指数、有效日期、条款和 URL 全部参数化。
   首版不提供在线规则编辑器。
4. 规则引擎采用类型化公式族：`cumulative_deviation`、`turnover_composite` 和
   `event_count`。Python 实现稳定公式，不包含具体板块阈值；不引入 JSON DSL、SQL 表达式执行或
   任意代码配置。
5. 首个规则集版本为 `cn-a-share-regulation-2026-07-06.v1`，包含26条规则记录：沪市主板9条、
   深市主板9条、创业板8条。规则生效日为2026年7月6日；首版不回算2023版本历史。
6. 价格偏离使用交易所规定的复合区间收益差，不把每日偏离值简单相加。窗口是“最多 N 个连续
   交易日”：对以目标日结束、未跨越官方重置边界的所有合法起点求值；上涨规则取最大值，
   下跌规则取最小值，并保存实际窗口起止日期。
7. 股票区间收益按每日官方参考前收盘价复合。公司行动所需输入来自 Capital 和可追溯行情事实；
   若发生除权除息但无法得到可靠参考价，该证券结果为不完整，不使用普通前收盘价近似。
8. 沪市主板基准指数为 `SSE:000002`，深市主板为 `SZSE:399107`，创业板为
   `SZSE:399102`。增加 BaoStock 专用白名单指数日线采集并写入现有 `core.daily_bar`；该能力不
   改变普通股票 Daily Bar 的 remote pytdx only 路由，也不以其他指数填补缺口。
9. `calculated_state` 与 `announced_state` 独立。计算状态为 `NORMAL`、
   `ABNORMAL_TRIGGERED` 或 `SERIOUS_TRIGGERED`；公告状态为 `NONE`、`ABNORMAL` 或
   `SERIOUS_ABNORMAL`。计算结果不得自动生成正式事件。
10. `regulation.event` 只接受交易所官网公开交易信息，或交易所官网托管且正文明确记录交易所
    计算结论的公告。首版自动事件类型仅为 `ABNORMAL_VOLATILITY` 和
    `SERIOUS_ABNORMAL_VOLATILITY`；方向不明确的事件可以保存，但不得计入同向次数。
11. 异常波动与严重异常波动分别维护官方重置边界。窗口从交易所公布的次一交易日或复牌日起
    重新计算。10日次数规则只统计正式确认的价格偏离型同向异常事件，换手率异常不计入。
12. T+1 只做规则条件反解，指数情景固定为 `INDEX_DOWN_2`、`INDEX_FLAT` 和
    `INDEX_UP_2`。情景是产品计算配置，不混入官方规则表。所有价格和比例使用 `Decimal`。
13. T+1 必须重新枚举滚动后的所有合法窗口，不能机械使用“阈值减当前累计偏离值”。上涨触发价
    按0.01元向上取整，下跌触发价向下取整；取整后重新代入公式验证，再按适用涨跌幅限制判断
    `REACHABLE_NEXT_SESSION` 或 `NOT_REACHABLE_NEXT_SESSION`。
14. 次数型严重异常的 T+1 路径必须标记 `requires_official_event_confirmation=true`；它只表示
    价格路径可能形成一次新的异常情形，是否计入次数仍以交易所正式认定为准。换手率条件不能由
    收盘价格单独反解，使用 `NOT_PRICE_CALCULABLE`。
15. 不使用 HIGH、MEDIUM、LOW 等主观风险评级。公开状态仅包括 `NOT_TRIGGERED`、
    `TRIGGERED_CALCULATED`、`ANNOUNCED_BY_EXCHANGE`、`REACHABLE_NEXT_SESSION`、
    `NOT_REACHABLE_NEXT_SESSION` 和 `NOT_PRICE_CALCULABLE` 等客观结论。
16. 第一阶段不适用于科创板、北交所、ST/*ST、退市整理期及无价格涨跌幅限制交易日。
    ST/板块/上市阶段无法可靠判定时，记录明确的不完整原因，不猜测适用性。
17. `regulation_daily_calculation` 在 Worker 代码任务目录中于交易日22:30执行基准指数采集、
    官方事件增量采集、依赖校验和版本化计算。`regulation_event_reconciliation` 于交易日08:30
    对账晚发布或更正事件，并为受影响日期创建新的计算版本。不得创建操作系统级定时任务。
18. 规则集无效、有效期重叠或交易日历不可用使整个批次失败；单个板块基准指数缺失只阻断该板块；
    单股行情、公司行动或适用性输入缺失只阻断该证券。批次必须记录完整、部分完成或失败及覆盖数。
19. 新增有界只读 RPC `api_v1.query_regulation_warnings`。调用方必须提供精确交易日，不回退；
    limit 为1至500，使用稳定键集分页，一次响应只读取一个已发布 `calculation_id`。
20. FastAPI 只包装该 RPC，不直接查询 `regulation` 或其他内部 schema，不触发采集、重算或写入。
    PostgREST、Agent Tools 和 FastAPI 三份契约同步更新。
21. 所有提示必须声明结果是基于公开规则的条件测算，不构成预测；实际认定及监管措施以交易所
    公开信息为准。规则触发与重点监控、核查、风险提示、停牌等 Regulatory Action 分开建模。
22. 生产启用官方网页采集前，项目所有者必须审阅交易所网站条款、访问频率、长期保存及再分发
    边界。审阅完成前只允许 mocked 测试和受控只读验证。

## 后果

- 阈值变化通过新规则版本和有效日期迁移处理，无需修改公式代码；公式语义变化仍需新算法版本和
  ADR。
- 正式事件、计算状态和监管措施不会混为一谈，消费者能够查看规则版本、算法版本和来源水位。
- 基准指数、ST状态、公司行动和官方事件来源成为明确的数据完整性依赖，缺失会产生可诊断的不完整
  结果，而不是近似值。
- 22:30 首次结果可能早于个别晚间公告；08:30对账和事件水位使这种暂态可见并可重算。
- 规则结果数量大于前端预警数量；`rule_result` 保留全量可审计结果，`warning` 只保留每个客观
  维度下最接近的确定性候选和已触发规则。

## 非目标

- regulation_snapshot、通用事件溯源平台或复杂工作流 DSL；
- 机器学习、价格预测、停牌概率、资金行为、龙虎榜、游资标签或交易建议；
- 科创板、北交所和 ST 特殊规则；
- 2026年7月6日前历史回算；
- 公开写接口、MCP、分钟/逐笔行情或动态规则管理后台。
