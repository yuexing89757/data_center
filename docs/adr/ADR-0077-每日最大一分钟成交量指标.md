# ADR-0077：每日最大一分钟成交量指标

- 状态：Accepted。2026-11-08项目所有者明确要求完成此前约定的每日指标及精确日期只读查询最小方案并上线，按该明确指令接受本文边界；不是以早先实验授权推定接受。
- 日期：2026-11-08。
- Issue：[#105](https://github.com/yuexing89757/data_center/issues/105)。
- 扩展：ADR-0001、0014、0015、0019、0024、0026、0043、0068。
- 设计：[每日最大一分钟成交量](../superpowers/specs/2026-11-08-daily-max-minute-volume-design.md)。
- 依据：[来源单位及差异核验](../minute-volume-unit-evidence-2026-11-08.md)。

## 目标与边界

只新增一个业务指标 `max_minute_volume_shares`：指定股票在指定交易日的合法一分钟
来源量柱最大值，单位整数股。消费项目自行选择前一交易日并绘图；中心不计算竞价比例或策略。
峰值时间、样本数、缺口和计算/认证版本是追溯元数据，不扩展业务指标目录。
不开放完整历史分钟行情接口，不建设分钟 Core 或分钟行情平台。

## 决策

1. 对分钟禁令作仅限本指标的例外：Worker 可有界读取 pytdx
   `get_security_bars(category=8)` 股票分钟数量和来源时间，用于本指标计算及必要输入证据。
   不扩展到 tick、逐笔、分钟 OHLC 对外服务或新的分钟任务。
2. 复用现有 20:30 `stock-daily-indicators-daily` 的工作流入口。日历确认开市后运行本指标
   独立步骤，再执行既有 Tushare 每日指标步骤及其保留清理。两个来源使用各自批次和血缘；
   不将 pytdx 派生值塞进 Tushare `core.stock_daily_indicator` 或伪造为同一来源批次。
   pytdx 步骤失败仍执行既有步骤，反之也不撤回已完成的本指标发布；Operations 如实记录各步骤。
   任一步骤失败而另一步骤成功时工作流必须为partial；全部业务步骤失败则为failed。
   不得捕获错误后直接调用当前的succeed()而错误标绿；Tushare保留清理仅在其采集前提满足时执行。
3. 只从现存 `PYTDX_POOL_PATH` 读取候选，不使用库默认节点、不为本任务刷新池。
   quote/daily capability 仅为既有登记；分钟适配器必须验证实际 category=8 响应。
   数量认证另按已核实的 peer/协议身份准入；未知身份即使返回240条也不得认证。
   当前核验证据限于 `103.251.85.94:7709` 的普通股票 category=8 字段，不能无条件推广其他节点。
   后续独立核验已覆盖同一peer的SSE/market1及SZSE/market0，各两只普通股票、两个交易日。
   BSE及其他peer尚未核实，不由沪深证据自动准入；完整对照和跨源差异见证据文档。
4. 来源身份为 `pytdx / get_security_bars / pytdx.stock_minute_volume.v1 / stock / volume`，
   category 必须为8；本次样本证据支持该 peer 的原值为股，不乘100。
   按 ADR-0068 分开记录单位认证与跨源数据差异；拒绝非整数股、负数、非有限值、溢出和未知单位。
   日 K 的手规则不变。接受本 ADR 后才登记新规则，不追认或修改既有认证。
   当前注册键及认证哈希尚不足以区分peer/category/market；正式实现必须扩展并版本化，
   将这些身份与证据版本绑定于Raw及认证，写入和重放都重新验证，不能仅检查适配器。
5. 对准确交易日筛选来源原生的 240 个结束时间标签：09:31–11:30、13:01–15:00。
   原样保留首尾量柱，不剔除、不额外叠加竞价量，也不将它们宣称为已经剥离竞价的纯连续交易60秒量。
   本次首根合并开盘量的对照证据及收盘边界未完全证明的部分必须明确披露。
6. 单位已证且目标日240条唯一合法标签完整时，纯计算器取最大值；并列峰值元数据取最早标签。
   标准值表示该来源报告的原生分钟量柱最大值，不承诺跨供应商逐股相等。
   已发现的13:26差100属于跨源数量差异，不能修补为另一来源的量、乘除100或据此撤销单位结论。
   它本身不阻止完整且单位已证的来源峰值发布；元数据和来源说明披露该已知差异，不能声称全源一致。
7. 缺失、重复冲突、截断、未知单位、未完成分页或无分钟能力均不得给出部分最大值。
   对受影响股票保留 null 与稳定原因；真实完整全零样本才可返回0。
   节点/市场无覆盖保持缺口，不跨源补齐，不因临时读取失败降低同日既有有效发布的覆盖。
   未知单位属于市场标准入库批次硬失败，不签发该批认证；派生层可记录批次缺口。
   首次计算若零有效结果则不发布快照，准确日期读取保持not_ready。
8. 复用 `derived.calculation_run`，增加不可变结果表和按日发布表；保存版本、输入哈希、
   Raw/认证引用及必要样本计数。内部 Raw 只保存计算所需时间/原生数量及协议证据，
   不存分钟 OHLC，遵循现有不可变性和保留规则，不新增在线分钟明细查询。
   本指标新对象首次写入即使用已有读取器支持的无损JSONL gzip表示；Manifest保留解压逻辑内容的
   哈希、字节和行数，逐对象精确重放校验。首次写入不生成或移除既有明文，不改变其他数据集
   的七天压缩和月度清除规则，不额外清理现有Raw或备份；避免新增来源证据压满生产磁盘。
9. 新增精确日期的有界 `api_v1` RPC 与 API-key FastAPI 查询，返回该日单一发布版本。
   不复用 `/latest/query` 的跨日语义，不从更早日期回退，不在请求中采集或写入。
   既有 latest 接口保持 ADR-0043 的原语义。契约细节与验收以关联设计为准。

## 执行门槛

先完成领域设计、ordered migration、聚焦测试及隔离数据库验证，再执行已授权的生产发布。
本次授权生产有序migration、Worker/API发布及明确样本的上线读取验证；不授权全历史回填或群消息。
迁移只走受保护GitHub流程。遵守宪法原则12，常规部署不创建数据库/Raw备份；
回退准备为旧Worker/API发行版及兼容的只增不删schema，不删除Raw、旧发布或旧认证。

正常每日计算读取目标日全量有效普通股票；上线核对仅对明确样本SSE:600327/2026-11-03执行一次，
其发布证据标明requested_symbols范围，不冒充全市场覆盖。已有同日有效集合不得因局部计算缩小。
来源身份按市场独立准入，未充分核验的市场保留缺口。HTTP只读持久化结果，不触发网络采集。

2026-11-08所有者后续另行授权11月2日至6日五交易日历史补算，随后将本次执行范围明确
收窄为消费项目“今日涨停”的351个准确日期/股票自然键（逐日108、47、96、71、29）。
该范围以消费项目只读导出的精确清单为准，不扩展全历史、其他指标、竞价或名单数据。
此前已启动但尚未发布的全市场尝试取消，现有Raw保留并登记为取消批次证据；
后续仅按这351组调用正式服务，逐日requested_symbols新版本发布。
11月3日原有单样本version1保留，由新发布版本替代，不无痕修改。
缺失保持null及原因；不触发消费端任务或群消息。执行和覆盖结果见既有实现文档。

所有者已另行明确授权先做本地隔离实验。`scripts/experiments/max_minute_volume_probe.py`
仅提供来源原值摘要，标准股数字段保持null，不加载生产配置、不访问数据库或调度。
早先实验本身不构成正式链路；正式接受依据是上面另行记录的生产交付指令。
