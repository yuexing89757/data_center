# ADR-0039：09:26 沪深主板一字涨跌停实时计算

- 状态：Accepted
- 日期：2026-08-17
- 跟踪：GitHub Issue #52
- 取代：ADR-0032 中“必须读取同日 `derived.daily_price_limit` CalculationRun”的决定

## 背景

09:26 全市场竞价快照在早盘已经持久化，但原查询还要求同日成功的晚间涨跌停派生批次，导致
来源事实 ready 后接口仍返回 404。该依赖不是一字板证据本身，也不满足早盘读取时效。

## 决策

`GET /api/v1/call-auction-one-price-limits` 保持只读，在
`api_v1.query_auction_one_price_limits(date)` 内基于选中的 09:26 快照请求时计算沪深主板上下限。
显式日期不回退；省略日期选择最新可用日期；同日优先 succeeded，没有 succeeded 才选择最新
partial。

主板普通股和 ST 股均按受控规则 `CN_MAINBOARD_2026_07_06` 的 10% 比例、0.01 元档位计算，
算法版本为 `1.0.0`。仅当正数且完整的
`last_price = high_price = low_price = upper_limit` 或 `lower_limit` 时归类。上市前五个交易日、
上市阶段无法证明、名称或报价不完整的主板记录显式计入遗漏；非主板不进入候选数。

该读取不访问 Provider、不触发采集、不使用后续日线、不写数据库，也不创建 CalculationRun。
响应 lineage 固定为：

```text
ingestion_id=<selected 09:26 ingestion>
price_limit_calculation_id=null
price_limit_rule_version=CN_MAINBOARD_2026_07_06
price_limit_algorithm_version=1.0.0
calculation_mode=realtime_read
```

RPC 保持 `stable security definer`、受控 search path 和 5 秒 statement timeout，只授予
`market_data_api`。不得加入 anon/authenticated PostgREST 或 Agent 工具契约。

## 后果

09:26 快照 ready 后接口即可返回 200；快照存在但没有严格命中时返回空列表。只有指定范围没有
可用 09:26 快照才返回 SQLSTATE `P0002`。`price_limit_calculation_id` 从必填 UUID 改为可空，
消费者改用 ingestion、规则、算法和计算模式重放结果。
