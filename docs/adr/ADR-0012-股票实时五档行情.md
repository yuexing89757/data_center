# ADR-0012：股票实时五档行情

- 状态：Accepted
- 日期：2026-08-02
- 关联 Issue：#27、#54
- 决策者：项目所有者
- 影响：扩展 ADR-0001 的行情范围；扩展 ADR-0005 的 Provider 能力矩阵；内部查询遵守 ADR-0010，外部 HTTP 暴露服从 ADR-0011

## 背景

看板、盘中监控和研究工具需要股票最新价及买卖一至五档的价格和挂单量。现有
Market 领域只保存盘后未复权 Daily Bar，不能表达盘中某一观察时点的盘口状态。

2026-08-02 的只读探测表明：

- pytdx `get_security_quotes` 能从部分公共行情节点取得最新价和买卖五档，但协议只
  解析到第五档，档位数量以“手”为主，公共节点可用性不稳定；
- pysnowball `pankou` 的响应 Schema 定义到十档，但普通 `level=1` 响应只有前五档，
  六至十档为空；客户端要求雪球 Cookie Token，接口和授权均非官方稳定契约；
- 两个来源的证券代码、时间、数量单位、缺档和闭市语义不同，必须在 Provider 边界
  统一，不能把来源字段直接暴露给 Pipeline 或 API。

本需求是客观行情事实，属于数据中心边界；但它新增网络实时源、采样频率、容量、
时效判断、凭据和再分发风险，必须先形成独立决策。

## 决策

1. 新增 `RealtimeQuote` 领域，首个聚合为 `FiveLevelQuoteSnapshot`，表示 Worker 在一个
   确定观察时点取得的股票盘口快照。它不是逐笔委托、逐笔成交、订单队列或交易所
   Level-2 数据。
2. 每个快照包含证券、观察时间、可选来源时间、最新价、昨收、开高低、累计成交量/
   成交额、行情状态，以及买卖各五个 `OrderBookLevel`。来源可能在集合竞价阶段返回
   “价格为零、数量为正”的未定价委托量；Adapter 必须将其标准化为 `price=NULL`、
   `volume=实际股数`。价格和数量均为零才表示空档并同时保存为 `NULL`，不得补零或复制邻档。
3. `observed_at` 是 Data Center 完整收到一次响应后的 UTC `timestamptz`，是快照自然
   身份的一部分，并写入 Raw。`source_timestamp` 是来源明确提供且可可靠转换时的
   上海时区时间戳；不得用当前日期静默拼接只有时分秒的来源字段并宣称为交易所时间。
4. 标准价格和金额使用 `Decimal`/PostgreSQL `numeric`；累计成交量和档位数量统一为
   “股”。pytdx 的“手”在 Adapter 内乘以 100，并记录来源精度质量信息；任何价格不得
   经过 `float` 进入标准 Record。
5. 已持久化的 Provider 身份包括 `pytdx_hq` 和 `pysnowball`，不得复用代表本地文件的
   `pytdx` 语义。当前运行时五档采集只使用 `pytdx_hq`；`pysnowball` 仅作为历史来源身份
   保留，不再注册运行时 Adapter 或自动回退。
6. pytdx Provider 在配置的节点允许列表内做启动健康检查，所选节点只进入采集参数和
   Raw，不进入领域事实。公共节点不可用、响应字段不完整或交易时段内快照过期均规范化
   为 `ProviderError`；不得回退到本地 Daily Bar 伪造盘口。
7. 历史 pysnowball Token 不进入仓库、Raw、IngestionRun 参数、日志或 API。移除运行时
   Adapter 后不再保留对应配置项；数据库中已存在的来源身份和历史事实不得改写。
8. 一个采集窗口只使用一个实际 Provider，不拼接两个来源的价和量。多源差异比较进入
   `audit` 报告，不自动仲裁或回写标准快照。
9. 标准快照采用 append-only 语义；相同 `(symbol, observed_at)` 内容相同可幂等跳过，
   内容冲突必须失败。来源修订不覆盖已观察到的历史盘口。
10. 首版只承诺 SSE/SZSE 股票。BSE 必须分别验证网络市场代码、代码映射和实际五档响应
    后才能声明支持；ETF、可转债、指数和板块指数不由股票验收结果推断覆盖。
11. 内部发布 authenticated 可执行的有界 PostgREST RPC，不授予 anon 实时行情权限。
    首个 RPC 为 `query_latest_five_level_quote`。外部 HTTP 若通过 ADR-0011 的 FastAPI
    发布，只能代理该 RPC 并复用其 API Key；不新增 WebSocket、独立服务或 MCP。
12. Core 只保存来源事实。价差、中间价、五档深度和盘口不平衡度是确定性客观计算，
    首版可由只读 View/RPC 计算，但公式与缺失值语义必须进入版本化契约；不发布买卖信号。
13. 首版只实现显式单次采集，不加入 `daily-run`，也不启动持续轮询。采样频率、单批
    证券数、Raw 分片、PostgreSQL 热数据保留期和清理方式必须通过容量压测后由后续 Issue
    接受；在此之前禁止全市场持续采集。
14. 使用任何上游数据前必须确认访问、缓存和再分发条件。未完成权限评估时，只允许本机
    诊断，不向外部客户端发布数据。

## 领域边界

```text
Security + Trading + Ingestion
              │
              ▼
       RealtimeQuote
       ├── FiveLevelQuoteSnapshot
       └── OrderBookLevel (value object)
              │
              ▼
       api_v1 bounded RPC
```

RealtimeQuote 不依赖 Daily Bar，也不修改 Daily Bar。盘后把快照聚合成 K 线、逐笔重建、
订单流推断、盘口情绪和交易策略均不在本 ADR 范围内。

## 生产持续采集前阻塞项

1. 确认 pytdx 与雪球数据的使用、缓存及再分发条件。
2. 在开盘连续竞价时验证至少 20 只 SSE/SZSE 股票，覆盖正常、涨停、跌停、停牌和无报价。
3. 验证数量单位、时间戳、累计量/额与来源客户端一致；记录 pytdx 手到股转换的精度损失。
4. 对 BSE 单独给出支持或暂缓结论。
5. 完成容量试验，决定采样间隔、每批规模、Raw 分片和热数据保留期。
6. 明确 authenticated 角色、网关频率限制和并发预算。

## 实现验收

- 领域 DTO、Validator、Provider 契约、Raw 重放、Persistence 和 API 契约均有测试；
- migration 从空库可重复执行，并验证 RLS、授权、索引和有界 RPC；
- 价格/金额全程使用 `Decimal`，档位和累计成交量统一为股；
- 缺档、陈旧、乱序、重复、交叉盘口和来源超时均有明确测试；
- Token、节点地址和 Provider 原始字段不泄漏到公开契约；
- `uv run ruff format --check .`、`uv run ruff check .`、`uv run mypy src` 和
  `uv run pytest` 全部通过。

## 后果

- 数据中心可以以统一、可追溯语义向看板提供最新五档快照；
- 实时采样不会污染未复权 Daily Bar，也不会被描述为交易所 Level-2；
- 需要承担网络源不稳定、凭据治理、容量与数据授权的新增运维成本；
- PostgREST/FastAPI 首版只支持客户端轮询。若出现真正推送或低延迟流式消费需求，必须以量化证据
  另建 ADR 评估流式基础设施。
