# ADR-0043：六位股票代码集合最新每日指标只读契约

- 状态：Accepted
- 日期：2026-08-22
- 关联 Issue：#61
- 决策者：项目所有者
- 扩展：ADR-0011、ADR-0014、ADR-0025

## 背景

`core.stock_daily_indicator` 已保存按 `(symbol, trade_date)` 标识的每日估值、换手率、
股本、市值和涨跌停状态来源事实，`api_v1.stock_daily_indicators` 也提供 authenticated
PostgREST 读取。外部消费者还需要按一组面向用户的六位股票代码，一次读取每只股票在 Core
热数据中现存的最新每日指标。现有 FastAPI 没有该契约，ADR-0014 的首期决定也未授权通过
FastAPI 发布该领域。

## 决策

1. 新增 authenticated FastAPI 只读接口
   `POST /api/v1/stock-daily-indicators/latest/query`。请求体字段 `codes` 接受 1–500 个
   `^[0-9]{6}$` 六位股票代码；重复代码按首次出现位置去重。
2. 数据库必须通过 Security 事实把六位代码解析为标准 `symbol`，不得依据代码前缀猜测交易所。
   同一六位代码若匹配多个交易所则整个请求以参数歧义返回 422。
3. 每个已解析 `symbol` 独立选择 `core.stock_daily_indicator` 中最大的 `trade_date`。
   不要求不同股票来自共同交易日；停牌、缺失或尚未采集的交易日不补造记录，也不回退到请求时
   Provider、Raw 对象或其他数据源。
4. 未知代码以及已知但 Core 当前保留窗口内没有每日指标的代码都进入 `missing_codes`。
   这些情况不使整个批量请求失败；全部缺失时返回 200、空 `items` 和完整 `missing_codes`。
5. 响应返回去重后的 `requested_count`、`found_count`、`missing_codes` 和 `items`。每项返回
   `symbol`、六位 `code`、`trade_date`，以及现有 `api_v1.stock_daily_indicators` 已公开的全部
   每日指标字段。`items` 与 `missing_codes` 均保持请求首次出现顺序。
6. Decimal 价格、百分比、倍数和市值继续序列化为十进制字符串；缺失值保持 `null`，零与缺失
   不得混淆。响应不暴露 `source_code`、`ingestion_id`、Raw 路径或其他采集技术字段。
7. FastAPI 只能调用新增的有界只读 RPC
   `api_v1.query_latest_stock_daily_indicators(text[])`。函数最多接受500个代码，固定5秒
   statement timeout，仅授权 `market_data_api`，不授权 `public`、`anon` 或
   `authenticated` PostgREST 角色。
8. 本 ADR 仅在上述批量最新查询范围内替代 ADR-0014“每日指标不引入 FastAPI”的决定。
   既有 PostgREST 视图、Core 一自然月保留、Provider、Raw、校验、采集和调度边界保持不变。

## 后果

- 外部消费者可以用稳定、受认证且有界的 HTTP 契约批量读取最新每日指标；
- “最新”是每只股票在当前 Core 热数据中的最新事实，不承诺所有结果具有同一交易日，也不承诺
  历史数据超过 Core 保留窗口后仍可查询；
- 新增 ordered migration、FastAPI 模型/查询/路由、中文 OpenAPI、文档和聚焦测试；
- 只更新 `contracts/fastapi-openapi-v1.json`，不新增 Agent Tool 或新的直接 PostgREST 表面；
- 接口只读，不触发采集、重放、计算、缓存或任何数据写入。

## 验收

- 覆盖 1/500 边界、空集合、超过上限、格式错误、重复代码、未知代码、无指标代码和跨交易所
  歧义；
- 测试证明每个 symbol 独立选择最新日期，停牌或缺失交易日不补齐，结果及缺失代码保持输入顺序；
- 测试证明 RPC 只读、有界、超时和最小权限，FastAPI 仅调用该 `api_v1` RPC；
- 401、422、503、中文 OpenAPI、Decimal 字符串与 `null` 语义均有契约测试；
- Ruff、mypy、完整 pytest 和隔离 PostgreSQL integration tests 通过；无法执行的检查必须报告
  具体命令和原因。
