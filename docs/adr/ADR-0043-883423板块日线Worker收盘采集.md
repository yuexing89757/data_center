# ADR-0043：883423 板块日线由 Worker 收盘采集

- 状态：Accepted
- 日期：2026-08-20
- 关联 Issue：#60
- 决策者：项目所有者
- 替代范围：替代 ADR-0036 的 FastAPI 实时兜底及异步写入决定；保留 ADR-0035 的计算公式
- 扩展：ADR-0003、ADR-0011、ADR-0017、ADR-0035、ADR-0036

## 背景

`GET /api/v1/board-indexes/883423/bias` 当前在数据库记录缺失、历史不足或陈旧时，
由 FastAPI 实时访问同花顺并异步写库。上游的短暂 HTTP 故障因此会直接影响查询
可用性，而且外部只读 API 进程获得了一个额外的受限写入边界。

项目所有者决定把 `THS:883423` 日线采集恢复为 Worker 的收盘后职责。查询接口只
读取已经持久化、具有 Raw 和 IngestionRun 血缘的数据库事实。

## 决策

1. 在 Worker 受控任务目录新增一个 `THS:883423` 日线任务。工作日固定在
   `15:30`、`16:30`、`17:30` 提供三个执行机会；调度时间属于代码，不允许由
   `.env` 配置。环境变量只允许启用或停用任务，默认启用。
2. 每次执行先根据 `CN_A_SHARE` 交易日历确定截至当天应有的最近交易日，并读取
   `core.board_index_daily_bar` 的最新日期。数据库已经覆盖目标日期时幂等跳过；
   存在缺口时采集一个有界日期范围，使后续执行机会和下一交易日能够自动补采。
3. 单轮上游请求最多进行三次有界短重试。重试只处理 Provider/网络失败，不吞掉
   校验、Raw、持久化或数据不变量错误；三轮调度均失败时保留失败执行事实，由下个
   交易日继续补采，不伪造或前向填充日线。
4. 采集复用 BoardIndex Daily Bar 标准 Pipeline。Provider 字段只在
   `akshare_ths` Adapter 内转换；成功批次只有一个实际 Provider，并保留不可变
   Raw、IngestionRun 和自然键幂等写入。
5. `GET /api/v1/board-indexes/883423/bias` 只调用有界 RPC
   `api_v1.query_board_index_bias_latest()`。FastAPI 不初始化该功能的 Provider，
   不捕获“未就绪”后实时抓取，也不排队写库。
6. RPC 最多读取最新 34 条已存储日线。至少 34 条时按 ADR-0035 计算并返回库内
   最新记录的真实 `trade_date`，即使当日数据尚未入库；少于 34 条或完全无数据
   时使用 `P0002`，由 FastAPI 映射为 404。
7. 删除 `market_data_api` 对实时持久化 RPC 的执行能力，并移除该写 RPC。API
   仍然不能直接访问内部 Schema，Worker 继续使用专用写角色。
8. 调度、重试、幂等跳过、缺口补采、API 数据库唯一读取、权限和公共契约均须有
   聚焦测试。生产变更只能通过有序 migration 和受保护部署流程执行。

## 后果

- 查询可用性不再直接依赖同花顺实时响应，接口稳定返回最近已入库交易日；
- 收盘后三次独立执行机会避免在 Worker 内部运行长时间阻塞循环；
- 当日数据可能短暂落后，但 `trade_date` 明确表达事实日期，不会把旧数据伪装成当日；
- API 恢复严格只读边界，所有来源事实统一经过 Worker 的 Raw 和 ingestion 血缘；
- 若连续多日上游失败，Worker 会持续补采，但 API 在历史达到 34 条后仍可读最近事实。

## 验收标准

- 工作日三个固定时点注册为同一受控任务，周末不执行，且 `.env` 无时间配置；
- 每轮最多三次短重试，成功后停止重试，已有目标日期时不访问 Provider；
- 缺失交易日能在后续时点或下一交易日补采；
- API 路径不访问同花顺、不产生 Raw、不写数据库；
- 数据库有 34 条以上时返回实际最新日期，不因未覆盖当天而回退 Provider；
- migration、权限、契约、ADR、领域文档和测试保持一致。
