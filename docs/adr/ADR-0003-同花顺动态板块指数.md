# ADR-0003：同花顺动态板块指数

- 状态：Accepted
- 日期：2026-07-28
- 决策者：项目所有者
- 关联：ADR-0001、ADR-0002

## 背景

项目需要采集同花顺“沪深主板昨日涨停”板块指数。该对象在同花顺的代码为 `883423`，可以获得日频 OHLC、成交量和成交额；其成分由“昨日涨停”规则按交易日动态变化。

它不是交易所挂牌证券，也不是普通行业分类。若直接写入 `core.security` 和 `core.daily_bar`，会混淆可交易证券、第三方板块定义和行情事实，并让证券生命周期字段失去语义。

AKShare 1.18.80 的同花顺板块目录当前未列出该动态板块，但底层同花顺历史行情端点可以按代码 `883423` 获取。生产实现不能依赖运行时篡改 AKShare 内部映射。

## 决策

### 1. 独立领域

新增 `BoardIndex` 领域，不把第三方板块指数映射为 `SecurityType.INDEX`。

第一期对象：

```text
board_id   = THS:883423
board_code = 883423
name       = 沪深主板昨日涨停
board_type = dynamic_theme
market     = CN_A_SHARE
```

`THS` 是板块标识命名空间，不是重复判断条件之外额外添加的数据来源字段。

### 2. 领域模型

建立三个 Core 对象：

#### `core.board_index`

板块指数定义和当前状态：

```text
board_id
board_code
namespace
name
board_type
market
status
source_code
ingestion_id
created_at
updated_at
```

自然键为 `board_id`，格式为 `<namespace>:<board_code>`。

#### `core.board_index_daily_bar`

板块指数不复权日 K：

```text
board_id
trade_date
market
open
high
low
close
volume
amount
source_code
ingestion_id
created_at
updated_at
```

自然键为 `(board_id, trade_date)`。`source_code` 不参与唯一性判断。价格和金额使用 `Decimal`/PostgreSQL `numeric`，不得通过 `float` 转换。

#### `core.board_index_constituent_snapshot`

记录每个交易日的动态成分股快照：

```text
board_id
trade_date
symbol
source_code
ingestion_id
created_at
```

自然键为 `(board_id, trade_date, symbol)`。由于“昨日涨停”每日重组，不把当前成分误建模为长期有效区间。

### 3. Provider 契约

新增独立能力契约：

```text
BoardIndexProvider
BoardIndexDailyBarProvider
BoardIndexConstituentProvider
```

该能力通过同花顺专用 Adapter 实现，并注册到现有 Provider Registry。Pipeline 只接收标准 DTO，不识别同花顺中文字段、页面路径或代码映射。

Provider 必须维护显式、受测试的板块目录，第一条为：

```text
THS:883423 -> 沪深主板昨日涨停
```

目录发现接口缺失该板块时不得把它判定为退市或删除。生产采集不得 monkey patch AKShare 私有函数；应使用公开能力，或在 Adapter 内封装并测试同花顺端点解析。

### 4. 来源语义

- 外部事实来源为 `ths`；
- 若由 AKShare 负责协议访问，采集实现标识为 `akshare_ths`；
- `source_code` 只用于追溯，不参与 Core 自然键和重复判断；
- 一个 ingestion run 只能对应一个 provider 和一个 dataset；
- Raw Store 必须保存来源响应、请求代码、日期范围、Schema 版本和内容哈希。

### 5. 数据集与采集顺序

新增数据集代码：

```text
board_index
board_index_daily_bar
board_index_constituent_snapshot
```

采集顺序：

```text
BoardIndex -> Trading Calendar -> BoardIndex Daily Bar -> Constituent Snapshot
```

日 K 必须关联已知交易日。成分股快照中的 `symbol` 必须存在于 `core.security`；未知证券记录质量错误并阻止该条 Core 写入。

### 6. 数据质量

至少检查：

- `board_id`、名称和显式目录一致；
- 日期在请求范围内且属于已知交易日；
- OHLC 非负，`low <= open/close <= high`；
- 成交量和成交额非负；
- `(board_id, trade_date)` 无重复；
- 成分股快照无重复且引用已知 `symbol`；
- 空响应、字段变化和无法解析必须使批次失败，不能写成零值或休市事实。

### 7. API

新增只读 API View：

```text
api_v1.board_indexes
api_v1.board_index_daily_bars
api_v1.board_index_constituents
```

客户端不得直接查询 Core 表。第一阶段不增加 FastAPI。

## 不在本次范围

- 自动发现和采集全部同花顺板块；
- 根据成分股自行复算同花顺指数点位；
- 分时、周线和月线；
- 自动多源故障切换；
- 主观周期、情绪或交易信号判断；
- 把板块指数伪装成可交易证券。

## 后果

### 正面

- 可保留同花顺特色指数，同时不污染证券领域；
- 动态成分股具有逐日可追溯快照；
- 自然键、来源和采集批次职责清晰；
- 后续可以在相同模型下增加其他第三方板块指数。

### 代价

- 需要新增三个领域对象、migration、Provider 能力和 API View；
- 同花顺页面或协议变化需要独立维护 Adapter；
- 指数点位依赖第三方定义，不能仅凭成分股完全复算验证。

## 验收标准

- 能按 `THS:883423` 采集并保存指定日期范围的不复权日 K；
- 能保存指定交易日的成分股快照；
- 重跑相同自然键不增加重复记录；
- 所有事实均可追溯到 ingestion run 和 Raw Manifest；
- Provider 契约测试覆盖字段变化、空响应、数值精度和未知成分股；
- migration、RLS、PostgREST View、Ruff、mypy 和 pytest 全部通过。
