# ADR-0055：Tushare 龙虎榜历史与游资席位画像

- 状态：Accepted
- 日期：2026-09-13
- 关联 Issue：#79
- 决策者：项目所有者
- 补充：ADR-0049、ADR-0053

## 背景

现有 DragonTiger 已保存龙虎榜事件、营业部席位行为、稳定席位身份和客观资金结构指标，并具备
EastMoney 日常采集及 Tushare `top_list`、`top_inst` 独立 Adapter。当前缺口是：最近两年仍可能存在
完全缺失的交易日；游资主体及其营业部席位关系没有可追溯事实；已有时点安全画像算法尚未形成
可查询的每日物化结果。

Tushare 的龙虎榜接口只披露事件和席位名称，不提供可靠的游资名录，也不为营业部提供稳定代码。
仅按名称自动合并会把同名、改名和泛化席位误认为同一主体。资金质量又包含主观判断，不能作为
Data Center 的事实或统一评分。

## 决策

1. EastMoney 继续负责日常 DragonTiger 采集。Tushare 仅作为显式的历史修复 Provider，用于最近
   两年中完全缺失的交易日；已有任何成功标准事实的日期不由 Tushare 覆盖或逐行补齐。
2. 一次成功 ingestion 只有一个实际 Provider。Tushare 事实保留独立 `source_code`、不可变 Raw、
   manifest 和 ingestion 血缘，不与 EastMoney 行拼接或仲裁。
3. 新增稳定游资主体和有效期游资—席位映射。Tushare `hm_list` 可作为游资名录来源；名录及映射
   最终仍由仓库内版本化清单维护，记录别名、证据说明、有效起止日期和审核状态。只有审核通过的
   映射参与查询和画像。
4. 禁止仅按营业部名称自动创建或合并稳定席位。`hm_detail` 的交易日期、股票、买入额和卖出额必须
   与已有稳定席位事实在来源披露的百元精度上精确且唯一匹配（金额按四舍五入归一到 100 元），且
   该游资—来源机构关系必须存在于 `hm_list`，才能生成待发布
   的 `APPROVED` 映射。无匹配、多席位匹配、同一来源机构跨席位或同一席位跨游资冲突均跳过并计数；
   不使用机构简称或名称相似度推断身份。
5. 新增版本化、按日物化的 `TradingSeatProfile`。画像只统计席位有效买入记录；纯卖出和净卖出记录
   不进入胜率样本。
6. 胜率采用未复权收盘到收盘收益。分别计算 T+1、T+3、T+5；收益严格大于零为胜，同时保存样本数、
   胜率和平均收益。停牌或缺失日 K 不得补值或制造样本。
7. 画像使用明确 `as_of_date` 和 `algorithm_version`。只有在 `as_of_date` 已可获得的后续收益才能进入
   样本；按某交易日查询时不得使用未来画像。
8. Worker 在龙虎榜与日线数据完成后每日物化画像，任务由代码任务目录和 APScheduler 注册，不增加
   操作系统级调度。
9. 新增一个有界只读契约，按必传交易日和六位股票代码返回龙虎榜资金结构、游资命中和历史席位
   画像。精确日期无数据时返回未找到，不回退其他日期。
10. Data Center 只提供净额、净买强度、集中度、机构/北向金额、游资命中、席位样本数/胜率/平均
    收益及质量码，不生成主观资金质量总分、席位等级或交易建议。
11. Tushare 历史修复按交易日独立提交、可断点续跑。运行前先以单日验证两个接口的权限和单位；
    最终报告覆盖日期、事件、席位、匿名比例、白名单命中率和失败日期。
12. Tushare token 只能通过运行时环境注入，不得写入 `.env`、代码、数据库、Raw、文档、契约、日志
    或 Git。
13. `hm_list` / `hm_detail` 目录构建是显式、有界、可审查操作，不加入 Worker 每日调度。两年数据
    按自然月分页获取以阻止单次 2,000 行上限静默截断；构建命令只输出版本化候选文件，数据库发布继续使用
    独立的确认命令并保持原子替换。

## 数据与契约

新增内部事实/派生对象：

- `HotMoneyActor`：稳定游资编码、标准名称、别名和启用状态；
- `HotMoneySeatMapping`：游资、稳定席位、有效期、证据、审核状态；
- `TradingSeatProfileDaily`：席位、画像日期、算法版本及 T+1/T+3/T+5 统计。

新公共查询只能通过 `api_v1` 有界 RPC 暴露。FastAPI 继续只调用 RPC，不读取 `billboard`、`core` 或
其他内部 schema。PostgREST、FastAPI 和 Agent Tools 三份契约必须同步。

## 后果

- 历史修复会优先提升日期覆盖，但匿名 Tushare 席位不会被虚构成稳定身份，因此席位画像覆盖率可能
  低于事件覆盖率；这是明确的质量边界。
- 人工名录是可审计事实目录，不是自动网络传闻聚合；每次变更都需要版本化审阅。
- 上层分析系统可基于客观组成指标自行定义资金质量评分，而不会把主观规则固化进数据中心。

## 实施条件

- Issue #79、领域详设和实现保持一致；
- ordered migration、RLS、Provider、Raw、服务、画像计算、Worker、公共契约及测试齐全；
- PostgreSQL 集成测试只使用隔离可丢弃的 `TEST_DATABASE_URL`；
- 生产回填前完成只读预检和单日冒烟，且不得输出或持久化临时 token。
