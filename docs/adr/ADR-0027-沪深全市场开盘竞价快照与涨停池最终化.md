# ADR-0027：沪深全市场开盘竞价快照与涨停池最终化

- 状态：Superseded（ADR-0028 继续接受晨间采集，并替代 Raw replay 与自动最终化部分）
- 日期：2026-08-11
- 关联 Issue：#41
- 决策者：项目所有者
- 扩展：ADR-0012、ADR-0017、ADR-0019、ADR-0022、ADR-0026

> 后续项目所有者决策见 ADR-0028：09:26 来源采集继续；本数据集 Raw replay 暂停；21:30 自动最终化
> 已移除且无替代计划。下文被替代的段落只记录原决策，不描述当前 Worker 调度。

## 背景

现有“今日竞价量”任务在 21:30 调用 `pytdx_hq.get_security_quotes`，此时来源的
`cumulative_volume` 和 `cumulative_amount` 已是全天累计值，不能证明为 09:25 开盘集合竞价
结果。只有在集合竞价最终撮合后、09:30 连续竞价前观察这些累计字段，才能把它们限定为本项目
所需的开盘竞价来源事实。

当日 ready 涨停池直到盘后才能确定，因此早晨不能只采最终涨停股。为避免盘后逐股读取历史
成交明细，本项目需要在早晨采集沪深上市股票全量来源快照，盘后再与精确日期的涨停池关联。

## 决策

1. 新增工作日 09:26 的受控 Worker 任务 `call-auction-market-snapshot-daily`，采集
   `core.security` 中 `SSE/SZSE + stock + listed` 的完整集合。BSE 暂缓，直到市场代码和实际
   五档响应通过独立 live validation；ETF、可转债、指数不进入股票全集。
2. 采集窗口固定为上海时间 `[09:25:00, 09:30:00)`。09:29:30 后不再发起新批次；任何
   `observed_at >= 09:30:00` 的记录都不能进入成功快照。任务时间只存在代码目录，`.env` 不得
   配置 hour/minute。
3. 每批最多 80 只，一个 IngestionRun 全程固定一个 quote-capable PYTDX endpoint。任一批次
   异常、证券缺失或重复时，该次运行标记 `partial` 并保留成功事实、Raw、Manifest 和质量结果。
4. 首 endpoint 未形成完整快照且窗口仍允许时，选择下一个 endpoint，从证券全集第一只重新
   采集并创建新的 IngestionRun。不得把多个 endpoint 的部分结果拼成一个 `succeeded` 批次；
   最多执行两个完整尝试。
5. 新增 append-only 内部事实 `realtime.call_auction_market_snapshot`，自然键为
   `(ingestion_id, symbol)`。每行保存精确交易日、Worker 观察时点、最新价、昨收、截至观察时点的
   当日最高价/最低价、累计成交量/额、source code 和 ingestion lineage。相同交易日的重试产生
   新 IngestionRun，不覆盖旧事实。
6. 新增 dataset code `call_auction_market_snapshot`。只有预期沪深 listed stock 全部有明确响应且
   所有硬校验通过时，IngestionRun 才能为 `succeeded`。停牌或来源明确返回的空行情保留为缺失
   值事实，不等同于未返回证券。
7. 纯数据库最终化实现保留为非调度内部能力；`call-auction-snapshot-daily`、其 scheduler entrypoint
   和旧 JobStore 记录由 ADR-0028 移除，不再在 21:30 或其他时间自动执行。
8. 内部最终化若被显式调用，仍要求完整覆盖精确日期 ready 涨停池，不发布部分结果；该规则不构成
   自动执行承诺。
9. `CALL_AUCTION_SNAPSHOT_ENABLED` 只控制 09:26 采集。不得增加替代时间、cron、timer、Windows
   Task Scheduler 或其他自动最终化。
10. 全市场晨间事实不新增公共 View/RPC。现有日涨停列表 API 继续只读取最终涨停池结果，字段和
    有界查询契约保持兼容。Raw 和 PostgreSQL 来源事实长期保留；首版不增加自动清理。
11. 本决策只接受每日一次的沪深全市场快照，替代 ADR-0012 中“容量验证前禁止全市场持续采集”
    对本用例的限制；它不接受逐秒、分钟、tick、逐笔、Level-2 或盘后历史成交抓取。

## 质量门禁

- 预期证券集合按标准 symbol 排序且唯一；响应必须与预期集合完全一致；
- `trade_date` 必须是统一日历交易日，观察日期必须等于该交易日；
- `observed_at` 必须带时区并落入 `[09:25, 09:30)`；
- 价格、金额和数量继续使用 ADR-0012 的 Decimal、元和股语义；
- 最高价/最低价允许来源缺失；非空时必须非负且最高价不低于最低价，非空最新价必须落在二者区间；
- 未知证券、BSE、重复响应、负数、越界时点和缺失响应阻止 `succeeded`；
- RawManifest 和来源 Raw 继续保留；在原冻结全集身份被确定性持久化并验证前，本数据集 replay
  fail closed，不能创建 succeeded replay；
- 内部最终化只选择精确日期最新成功 ingestion，不读取 JSON request parameters 猜测日期。

## 容量与运行边界

当前沪深上市股票约 5,200 只，即每个 endpoint 约 65 个顺序批次。单 Worker、单 endpoint、
最大 80 只/批的边界保持固定，不引入并发洪泛。09:29:30 是发起请求的硬截止，09:30 是事实
观察时点的硬截止。上线后以实际批次数、总耗时、失败证券数和 endpoint attempt 数完成 live gate；
不手工补造此前交易日。

## 后果

- “今日竞价量”不再把收盘累计量误称为开盘竞价量；
- 早晨来源事实与盘后涨停池派生分离，lineage 可追溯且失败可见；
- 每年约新增 130 万行内部来源事实以及对应 Raw，对当前 PostgreSQL 容量可控；
- 新 migration、Operations workflow code、调度任务和运维验收均需同步更新；
- 北交所保持显式缺口，后续支持必须另建 Issue 和 ADR clarification。

## 验收

- 单元测试覆盖沪深全集、BSE 排除、80 只分批、时间窗口、单 endpoint 完整性和全量重试；
- PostgreSQL 集成测试覆盖 migration、append-only、RLS、权限、精确成功批次选择和事务最终化；
- 内部最终化测试证明 Provider 不可达时仍只使用晨间数据库事实；
- Worker 目录和本地管理页只显示 09:26 任务，且清理旧 `call-auction-snapshot-daily` JobStore 记录；
- 公共 OpenAPI/Agent/FastAPI 契约无非预期差异；
- Ruff、mypy、全量 pytest 和隔离 PostgreSQL integration tests 通过。
