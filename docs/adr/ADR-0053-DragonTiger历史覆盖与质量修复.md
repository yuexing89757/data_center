# ADR-0053：DragonTiger 历史覆盖与质量修复

- 状态：Accepted
- 日期：2026-09-08
- 关联 Issue：#70
- 决策者：项目所有者
- 补充并部分替代：ADR-0049 第 1～8、12 项的周期、席位别名、采集事务与公共契约细节

## 背景

DragonTiger v1 上线后，对 2025-01-01 至 2026-09-03 的历史回补留下 375 个失败交易日。
失败证据表明原设计对真实来源作了四项不成立的假设：

1. `period_type` 只有 `DAY` 和 `THREE_DAY`，且三日原因只识别中文数字；真实来源还存在阿拉伯
   数字三日、连续 10/30 个市场交易日、窗口内多次同向异常，以及北交所“最近 3 个有成交的
   交易日”等客观触发规则。
2. 来源席位代码和席位名称被分别设为全局唯一身份；真实席位代码会发生历史改名，同名也可能
   出现在不同来源身份上。
3. 东财会返回完全重复的明细行、零买零卖的“深股通投资者”占位行，以及只披露买榜或卖榜一侧
   的事件。这些来源表现不应令整个交易日丢失，也不能降低 `SeatTrade` 的非零硬约束。
4. Raw 在事实事务前已写入文件系统，而 ingestion、manifest、席位解析和事实发布在同一数据库
   事务中。后段失败会回滚全部数据库血缘，留下孤儿 Raw。

另有北交所证券主数据缺口：默认 BaoStock 证券批次成功后不会调用 AKShare，而 BaoStock 不提供
完整北交所目录；AKShare 当前目录又不能恢复已退市证券。仓库既有 Tushare `stock_basic` Adapter
能够读取 `L/D/P` 状态和 `.BJ` 代码，可作为独立的北交所证券批次使用。

对真实东财响应的复核还确认：汇总和席位明细只有披露交易日与原因文本，没有独立、可验证的
“席位金额统计周期”字段。触发规则窗口不能被静默当作金额统计周期。

## 决策

1. 用通用窗口语义替换 `DAY|THREE_DAY` 枚举身份。Event 分别保存上榜触发窗口和金额统计周期，
   不再以 `period_type` 表达两种不同概念。
2. 触发窗口保存 `trigger_window_basis`、`trigger_window_sessions`、可空
   `trigger_occurrence_count` 和可空 `trigger_start_date`。窗口基准至少支持市场交易日和证券实际
   有成交交易日；结束日等于披露交易日。
3. 金额周期保存 `amount_period_basis`、可空 `amount_period_sessions` 及可空起始日/结束日。
   只有来源字段或已验证的来源展示语义能证明周期时才填写具体周期；否则明确使用
   `SOURCE_UNSPECIFIED`，禁止从原因窗口猜测。
4. 原因映射负责把已验证来源原因映射为稳定原因类型和触发窗口。未验证的新原因继续失败关闭，
   并产生稳定错误码；不得使用模糊包含判断虚构语义。
5. 可靠 `source_seat_key` 是来源身份。新增来源身份记录，以
   `(source_code, source_seat_key)` 唯一映射稳定 `seat_id`；名称只是该身份带首次/末次观察日期的
   Alias。同名可属于不同来源身份，改名不得切断席位历史。
6. 无可靠代码的泛化“机构专用”等记录继续保持 `seat_id=NULL`。不得仅按名称自动合并或创建稳定
   身份。
7. 东财完全重复来源行在 Raw 中原样保留，在标准化时确定性去重并记录质量码。明细报告超过一页
   时按当日汇总中的 `TRADE_ID` 有界逐事件读取，避免仅按非唯一 `TRADE_ID` 全局分页导致漏行或
   重行。计数或非完全重复冲突仍失败关闭。
8. 买卖金额都明确为零的来源占位行保留在 Raw，但不创建 `SeatTrade`，并记录事件可定位的质量码
   和过滤数量。`SeatTrade` 的非负、非双空、非双零硬约束保持不变。
9. 只披露买榜或卖榜一侧的 Event 正常发布；缺失侧保持 `NULL`，公开契约显式返回披露完整性。
10. DragonTiger ingestion 改为分阶段持久化：先登记 `RUNNING`，Raw 落盘后立即登记 manifest，
    再以独立事务发布质量结果和标准事实；失败使用独立事务记录稳定错误码并保留 Raw/manifest。
    僵尸运行沿用 ADR-0006 的恢复机制。
11. 增加 Worker Catalog 内的 `security_bse_daily` 任务，显式使用 Tushare 获取 `L/D/P` 后仅发布
    BSE 证券。它是独立 ingestion，不与 BaoStock/AKShare 合并；DragonTiger 日任务在其后运行。
12. 日期和股票 DragonTiger RPC/FastAPI 查询删除 `period_type` 参数，改用可选触发窗口基准和
    会话数；Event、席位历史和指标响应增加窗口、金额周期、披露完整性及安全质量码。旧函数签名
    由 ordered migration 明确删除，三份 checked-in contract 同步更新。
13. 增加限定于 DragonTiger Raw 根目录的孤儿恢复命令。它必须验证路径、ingestion UUID、JSONL、
    哈希、行数和交易日后，补登记失败 run/manifest，并标记 `DT_RECOVERED_ORPHAN_RAW`；不得修改
    Raw 文件。
14. 所有可预期失败使用稳定代码。日志、operations 和公开质量信息不得包含来源负载、凭据、
    数据库地址或任意底层异常文本。

## 数据质量与分析语义

- `SOURCE_UNSPECIFIED` 是已知的来源限制，不等于单日或零日。
- 单侧披露不会阻止与已披露侧无关的客观指标；依赖缺失侧完整性的指标返回 `NULL`。
- 质量码必须随 Event/metrics 公共读取返回，使消费者能够按完整性筛选训练和分析样本。
- 过滤来源占位或完全重复行不是降低领域硬约束；这些行没有形成有效经济行为事实，Raw 仍提供
  完整审计和重放证据。
- 本 ADR 不引入主观资金质量评分、游资身份或交易建议。

## 发布与回补

生产发布按 migration、Worker/FastAPI、BSE 全状态证券同步、孤儿 Raw 恢复、现有 Raw 重放和缺失
日期重新抓取的顺序执行。历史范围为 2025-01-01 至运行时最近一个已收盘交易日。每个交易日独立
提交；单日失败保持显式缺口但不阻断后续日期，最终必须报告覆盖率和剩余稳定错误码。

本次生产变更由项目所有者明确要求不创建数据库备份；执行前仍必须完成只读 migration 预检、
精确目标核对和服务健康检查。

## 后果

- 当前 DragonTiger 公共契约再次发生破坏性前向替换，消费者必须同步字段和过滤参数。
- 10/30 日和北交所触发事件可以作为客观事实入库，但金额周期未经证明时不能与已验证单日/三日
  样本混合计算。
- 每次采集多一个或两个短事务，换取失败 Raw、运行状态和质量证据的持久可追溯性。
- Tushare 凭据和来源权利仍是启用 BSE 证券任务的生产门禁；检查不得输出 token。

## 实施条件

- 领域详设、migration、三份公共契约和 Issue #70 保持一致；
- Provider、Raw replay、Domain、Service、Persistence、API、scheduler 和 orphan recovery 均有
  聚焦测试；
- PostgreSQL 集成测试仅使用 `TEST_DATABASE_URL` 指向隔离可丢弃数据库；
- 完整本地质量门通过后方可推送和部署。
