# 同日涨停快照领域详设

## 口径与主键

- 交易日按 `CN_A_SHARE`/Asia/Shanghai，不回退到旧日期。
- 快照自然键 `(trade_date, version)`，成员自然键 `(snapshot_id, symbol)`。
- 涨停是未复权 close 精确等于当日版本化 upper limit；来源榜单不决定成员资格。
- `change_percent = (close / previous_close - 1) * 100`，单位为百分点。
- 价格 `numeric(18,4)` CNY/share，比率 `numeric(24,10)`，股数 `bigint` shares，
  金额 `numeric(30,4)` CNY。

## 来源映射

AKShare/Eastmoney 当日榜单仅映射：代码、来源名称、首次/末次封板时间、炸板次数和
来源报告封板资金。名称以 `core.security_name_history` 当日有效区间为准；价格来自
`core.daily_bar`；流通股数仅来自 `metrics.stock_daily_indicator.free_float_shares`。
来源流通市值不入规范字段。

## 质量与修订

缺历史名称、close、previous close、limit price 或 free-float shares 时逐行拒绝，快照为
`partial`；不补值。缺 AK 封板富化或收盘五档时保留成员，字段为 NULL 并记 warning。
`open_count >= 0`，0 与 NULL 不同；首次不得晚于末次。任何来源或上游修订都创建新
version，旧版本永不更新。`content_hash` 覆盖排序后成员内容，`input_hash` 覆盖
精确上游版本/ingestion。

## 22:00 任务

`today-limit-up-snapshot-daily` 是 Worker 内 APScheduler cron，周一至周五 22:00。先确认
当日为交易日，再检查同日 daily_market、stock_daily_indicator 及精确 basis date 的
ready 涨停池。依赖不足时仅封存 deferred 快照及原因，不调来源、不发布 ready。
重试使用 input hash 幂等。手工命令必须显式提供 `--trade-date`，不隐式选择“最新”。

```bash
uv run market-data-center today-limit-up-snapshot --trade-date 2026-08-11
```

`TODAY_LIMIT_UP_SNAPSHOT_ENABLED` 默认为 `false`。只有在迁移已应用、Worker 角色权限已验证、
Raw 持久目录可写、且服务器能访问 AKShare/Eastmoney 当日涨停来源后才可改为
`true`。来源公共节点无 SLA，返回结构变化或超时会使 ingestion 失败，不会将部分
来源响应标记为 ready。
`TODAY_LIMIT_UP_TIMEOUT_SECONDS` 默认 10 秒，`TODAY_LIMIT_UP_MAX_ATTEMPTS` 默认 2；
每次 HTTP 请求都被强制超时，重试仅在整个请求抛错后发生，不合并两次响应。

## 运维检查

上线前必须在隔离 PostgreSQL 运行迁移/权限集成测试，确认 Worker 只能 insert/select，
公开 API 角色无底表权限。上线需独立授权：先备份并验证恢复证据，再应用单一迁移、
部署 Worker 代码，最后核对调度目录；本次未执行任何生产操作。
